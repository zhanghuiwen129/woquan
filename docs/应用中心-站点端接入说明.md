# 应用中心 · 站点端接入说明（我圈）

> 版本：v1.0（2026-11-20）
> 定位：我圈源码开源、可被任意站点部署；**应用中心是唯一服务端**。
> 本文档面向：① 站点管理员（如何接入、安装、授权、校验）；② 开发者（如何打包扩展）。
> 协议权威：`D:/woquanyingyong/docs/应用中心-中心化接入协议.md`（该协议在独立仓库 `D:/woquanyingyong`，离线部署者无法从本仓查阅）。

---

## 1. 它是什么

我圈后台「系统与运维 → 应用中心」页，是一个**连接中心服务端的客户端（agent）**：

- 商品、支付、购买码、版本分发 → 全在**应用中心**（商业平台）
- 本站只做：注册身份 → 浏览市场 → 激活购买码 → 下载安装 → 检查更新 → 校验篡改
- 站点离线或中心宕机时，我圈主程序照常运行，只是装不了新扩展

一句话：**开源主程序负责铺量，应用中心负责收钱；本站后台只是入口。**

## 2. 管理员操作

### 2.1 首次接入（一次）

1. 进入「应用中心 → 设置与校验」Tab。
2. 填 **API 地址**：应用中心的 `api.php` 地址，例如 `http://你的域名/api.php`（本机默认 `http://127.0.0.1:8080/api.php`）。
3. 点「保存地址」，再点「测试连接」。
4. 填站点名称，点「注册新站点」。
5. 成功后本站拿到 `site_key` / `site_secret` 并保存到本机 `settings` 表：
   - `app_center_api` / `app_center_site_key` / `app_center_site_secret` / `app_center_site_name`
   - `site_secret` 是隐私凭据，页面只显示掩码，且**仅注册时由中心返回一次**；丢失需中心后台重新生成或重新注册。

> 若中心配置了 `SITE_AUTO_APPROVE=0`，新站点状态为 `pending`，需中心后台审核通过才能调用 API。

### 2.2 浏览与安装

1. 「应用市场」Tab 列出中心已上架应用，可按名称/描述搜索。
2. 每项显示类型（插件/主题）、最新版本、价格与授权状态。
3. 点「安装 / 更新」：本站会依次执行
   - 调中心下载 zip（带 HMAC 签名）
   - 校验响应头 `X-Package-Hash`（sha256），不符则拒装
   - 安全解压（拒绝 Zip Slip / 绝对路径 / 符号链接 / 超限）
   - 插件：适配成我圈格式后部署到 `plugins/{PascalCase}/`
   - 主题：部署到 `templates/{slug}/`
   - 覆盖前自动备份到 `cache/app-center-backups/`
   - 写安装记录 + 建立完整性基线
   - 向中心上报已安装版本

安装结果里的 `warnings` 会提示适配过程中的注意项（如自动注入了 `init()`）。

### 2.3 购买码授权

1. 在应用中心购买主题/插件后获得购买码（形如 `LIC-XXXX-XXXX`）。
2. 「购买码」Tab 输入后点「激活购买码」。
3. 校验规则：状态正常 / 未过期 / 激活站点数 < 上限 / 本站未激活过该应用（重复激活幂等）。
4. 「本站已激活授权」列出已激活项与到期时间。
5. 付费应用未激活时，下载会被中心拒绝（402），页面提示「需要先购买并激活授权」。

### 2.4 检查更新

「应用市场 → 检查更新」会带本站已装版本询问中心，列出 `已装版本 → 最新版本`，逐项点安装即可更新。

### 2.5 完整性校验（查篡改）

「设置与校验」Tab 下：

1. 首次对某扩展点「建基线」：扫描目录内所有文件（排除 `vendor/uploads/cache/logs` 等可变目录），记录 sha256。
2. 之后点「校验」：显示三类差异
   - **modified**：文件内容被改
   - **added**：新增了文件
   - **deleted**：文件被删除
3. 状态 `ok` = 未被篡改；`tampered` = 检测到改动；`no_baseline` = 尚未建基线；`missing_dir` = 基线记录的目录已不存在。
4. 商业意义：确认从应用中心装的付费扩展有没有被本地改代码 / 破解 / 二次分发。
5. 基线存在 `cache/app-center-baselines/`，可删除重建。

### 2.6 卸载

「已安装」Tab 对应用中心来源的扩展点「卸载」：删除目录前自动备份到 `cache/app-center-backups/`，同时清除安装记录与基线。

## 3. 数据存储与不改动项

| 数据 | 位置 | 说明 |
|---|---|---|
| 中心地址 / 站点凭据 | `settings` 表（`app_center_*`，含 `app_center_auto_check`） | 复用现有表，不改结构 |
| 已安装扩展记录 | `cache/app-center-installs.json` | 版本 / 来源 / app_id |
| 完整性基线 | `cache/app-center-baselines/*.json` | 文件清单 + sha256 |
| 覆盖/卸载备份 | `cache/app-center-backups/` | 可回滚 |

**未改动**：我圈的数据库结构、现有插件/主题加载机制、现有扩展管理页。全部为增量新增。

### 签名算法（与中心字节级一致）

```
CANONICAL = ksort(所有业务参数，值字符串化) → json_encode
STRING    = METHOD + "\n" + PATH + "\n" + TIMESTAMP + "\n" + NONCE + "\n" + sha256(CANONICAL)
SIGNATURE = base64url( HMAC_SHA256(site_secret, STRING) )
```

四个请求头：`X-Site-Key` / `X-Site-Timestamp` / `X-Site-Nonce` / `X-Site-Signature`。签名时间戳容差 `SIGN_TTL=300` 秒（`AppCenterClient.php:22`）。
GET 参数进 query，POST 参数进 JSON body（保留类型），签名覆盖全部业务参数（不含路由控制参数 `s`）。

## 5. 开发者：如何打包扩展

### 5.1 插件包

zip 内**单一顶层目录**（如 `ContentAudit/`，须与清单 `name` 一致）：

```
ContentAudit/
├── plugin.json        # 清单（必需）
└── Plugin.php         # 入口（必需）
```

`plugin.json` 字段：

```json
{
  "name": "ContentAudit",
  "title": "内容审核",
  "version": "1.2.0",
  "description": "AI 内容审核",
  "author": "你的名字"
}
```

`name` 必须以字母开头、仅含字母数字，且等于顶层目录名；`type`、`entry` 不是 `plugin.json` 的合法字段，写入清单会被 `PluginManifest` 判为非法。安装器只改写 `Plugin.php`（注入 docblock、命名空间、`init()` 与 Hook 适配），不重写 `plugin.json`：包内清单本身必须通过 `PluginManifest` 校验，否则安装成功但不会被加载。

`Plugin.php` 用应用中心规范写（安装时自动适配成我圈格式）：

```php
<?php
namespace AppCenter\Extension\Plugin\ContentAudit;

use AppCenter\Services\HookEngine;

class Plugin
{
    public function boot(HookEngine $hooks): void
    {
        $hooks->addAction('post_created', [$this, 'onPost']);
    }
    public function onPost($post): void {}
}
```

这里用 `addAction()`：`Hublog\Core\Hook` 只提供 `addFilter` / `applyFilter` / `hasFilter` / `addAction` / `doAction` / `hasAction`，没有 `on()`。安装时 `$hooks->` 会被适配为 `Hook::`，即上面的调用变成 `Hook::addAction(...)`。

安装器会自动完成：
- 按清单 `name` 计算部署目录 `ContentAudit`（PascalCase），与包内顶层目录名一致
- 命名空间 → `Hublog\Plugin\ContentAudit`
- `boot(HookEngine)` → `init()`
- 注入 `@name/@version/@description/@author` docblock：仅在无 `plugin.json` 时作为回退信息被读取
- `$hooks->` → `Hook::` 字符串替换（如 `addAction` → `Hook::addAction`，静态类为 `Hublog\Core\Hook`）

`Plugin::scanAll()` / `Plugin::loadAll()` 先走 `PluginManifest::fromDir()`，清单非法直接跳过该插件；有 `plugin.json` 时以清单为准，docblock 仅在无清单时回退。

### 5.2 主题包

```
your-theme/
├── theme.json         # 必需
├── contract.json      # 建议（契约校验）
├── index.html         # 主页骨架
├── apps.html          # 应用页骨架
└── app.html           # 详情页骨架
```

主题直接复制到 `templates/{theme.json 的 id}/`，不做命名空间适配。缺文件会在安装结果 `warnings` 里提示。

## 6. 验证与已知边界

- `php tests/appcenter_agent_probe.php`：签名一致性 / 配置 / 安装适配 / sha256 拒装 / 基线 / 篡改 / 卸载等检查（脚本含异常分支，项数以实际输出为准），全绿。
- `php tests/appcenter_http_smoke.php`：5 项全链路（真实 admin JWT → 路由 → 鉴权 → 控制器），全绿。
- 我圈 phpunit：以 `php vendor/bin/phpunit -c phpunit.xml.dist --no-coverage` 实际输出为准。
- 全项目 PHP lint + JS `node --check` 通过。
- 真 MySQL 已在本机验证连通与 settings 读写。
- 边界：付费包交付到站点后无法做到绝对防破解（PHP 开源程序共性）。建议核心逻辑放中心服务端 API，本地只留壳；完整性校验作为辅助检测手段，不作唯一防线。
