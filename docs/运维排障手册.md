## 2. 日志

### 2.1 文件清单

| 文件 | 内容 | 写入方 |
| --- | --- | --- |
| `logs/hublog-YYYY-MM-DD.log` | 应用日志 | `api/core/Logger.php` |
| `logs/access-YYYY-MM-DD.log` | 访问日志（单行 JSON） | `api/core/Logger.php::access()` |
| `logs/php-error.log` | PHP `error_log` 目标 | `api/index.php:12` |
| `logs/.rotate_marker_YYYY-MM-DD` | 每日轮转并发标记 | `Logger.php::rotateIfNeeded()` |
| `cache/.migration_failed` | 迁移失败标记 | `api/core/Migration.php` |

前台入口 `index.php` 未设置 `error_log`，其 PHP 错误落到 PHP 默认目标。

### 2.2 格式

| 日志 | 单行格式 |
| --- | --- |
| 应用 | `[YYYY-MM-DD HH:MM:SS][LEVEL] 消息 {JSON ctx}` |
| 访问 | `{"time","ip","method","uri","status","duration_ms","user_id","referer","ua"}` |

访问日志的 `ua` / `referer` 截断到 512 字节，不记录 Authorization、Cookie 与请求体。查询串中 `token` / `access_token` / `refresh_token` / `code` / `password` 的值替换为 `***`，该脱敏只作用于 `access()`。

### 2.3 保留与清理

| 规则 | 值 |
| --- | --- |
| 按日切分 | 文件名中的 `date('Y-m-d')` |
| 保留天数 | `14`（`Logger::DEFAULT_RETENTION_DAYS`） |
| 轮转触发 | 每天首次写入，`fopen($marker,'xb')` 原子抢占 |
| 删除范围 | 日期早于 `today-14d` 的 `*.log`；无日期后缀的 `.log` 需 mtime 早于 28 天 |
| 保留天数配置 | 硬编码在 `api/core/Logger.php:11` |

`logs/php-error.log` 无日期后缀且持续写入，不参与 14 天清理，需外部轮转：

```text
/etc/logrotate.d/woquan
/path/to/woquan/logs/php-error.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
    copytruncate
}
```

### 2.4 `error_id` 定位

`error_id` 为 8 位十六进制，只出现在未捕获异常 500 与 FATAL 兜底响应。业务 4xx、JWT 失败、`HublogException` 响应不带该字段。

```bash
grep -rn '\[Uncaught 1a2b3c4d\]' logs/hublog-$(date +%F).log
grep -n '\[Hublog FATAL 1a2b3c4d\]' logs/php-error.log
grep -n '\[Hublog Uncaught\]' logs/php-error.log
```

`APP_DEBUG=true` 时 500 响应另含 `error_class` 与 `debug{file,line,trace}`。

## 3. 缓存

### 3.1 目录内容

| 条目 | 用途 | 可删 |
| --- | --- | --- |
| `*.cache` | 序列化缓存值，文件名 `md5($key)` | 是 |
| `lock_*.lock` | `flock` 锁文件 | 是 |
| `*.cache.*.tmp` | 原子写临时文件 | 是 |
| `.schema_verified` | 迁移快路径标记 | 否 |
| `.schema_version` | 当前迁移版本号（与 `schema_versions` 表双写，DB 优先） | 否 |
| `.migration_failed` | 迁移失败标记 | 否 |
| `.gitkeep` | 目录占位 | 否 |
| 根目录 `.installed.lock` | 安装锁 | 否 |

删除 `.installed.lock` 后：前台 302 跳 `install.php`，API 返回 `503 系统尚未安装`。旧路径 `cache/install.lock` 仍被兼容识别。

### 3.2 驱动与键

| 项 | 值 |
| --- | --- |
| 驱动 | `CACHE_DRIVER` = `file`（默认）/ `redis` |
| Redis | `REDIS_HOST` `127.0.0.1`、`REDIS_PORT` `6379`、`REDIS_DB` `0`、超时 `2.0` |
| 前缀 | `CACHE_PREFIX` = `hublog_` |
| 降级 | 扩展缺失 / 连接失败 / 读写失败 → 回退 `file` |
| 默认 TTL | `CACHE_TTL` = `3600` |

| 键 | 用途 | 失效方式 |
| --- | --- | --- |
| `site_settings` | `settings` 表全量 | `Cache::delete('site_settings')` |
| `nsver_<ns>` | 命名空间版本（TTL 604800） | `bumpNsVersion()` / `bumpNsVersionThrottled()` |
| `rate_limit_<action>_<identity>` | 限流计数 | 按窗口自然过期 |
| `csrf_<token>` | CSRF 载荷 | `CSRF_TOKEN_EXPIRE` = `3600` |
| `sse_user_<uid>.json` | SSE 事件队列，最多 100 条 | 消费后清理 |
| `app_version_<platform>` | 客户端最新版本，TTL 300 | 后台版本变更后自动过期 |

`remember()` 使用单航班锁与锁内双重检查；`withLock()` 加锁失败时降级为非原子执行。

### 3.3 清理命令

```bash
rm -f cache/*.cache cache/lock_*.lock cache/*.cache.*.tmp cache/.index
chmod -R 755 uploads/ cache/ logs/
```

禁止 `rm -rf cache/*`。`Cache::flush()` 的删除范围与上面命令一致，不触碰 `.schema_verified` / `.schema_version` / `.migration_failed`。

### 3.4 迁移快路径

| 条件 | 值 |
| --- | --- |
| 标记格式 | `{"version":<int>,"time":<unix>}` |
| 命中条件 | `version >= 101` 且 `time() - time <= 300` |
| 命中效果 | 跳过全部迁移相关 SQL |
| 失效方式 | 删除 `cache/.schema_verified`，或等待 300 秒 |
| 重装时的处理 | `install.php` 调 `Migration::resetState()` 删除标记 |

`cache/.schema_version` 与 `schema_versions` 表是版本双写：`Migration::getInstalledVersion()` 以 DB 的 `MAX(version)` 为准并回写文件，DB 不可用才降级读文件；`saveVersion()` 先写 DB（写失败抛错并中止迁移），再写文件并刷新 `.schema_verified`。

排查「代码已更新但表结构没变」时，先删该标记再重跑一次请求。

## 4. 健康检查

`GET /health` 免鉴权、免限流、无中间件，HTTP 状态码**始终 200**，必须读 `data.status` 判定。

| 字段 | 值 |
| --- | --- |
| `data.status` | `ok` / `degraded` / `down` |
| `data.time` | ISO8601 |
| `data.checks.db` | `SELECT 1`；`ok/connected` 或 `down/db unreachable` |
| `data.checks.cache` | 返回驱动名；set/get 不一致 → `degraded` |
| `data.checks.disk` | 探测 `uploads/`；剩余 `<2%` → `down`，`<10%` → `degraded`；带 `free_mb` / `total_mb` |
| `data.checks.migration` | 无失败标记 → `ok/no recent failure`；有标记 → `down` 并带 `target_version` / `error` / `time` |

```bash
php -r '$j=json_decode(file_get_contents("https://example.com/health"),true); echo $j["data"]["status"], PHP_EOL;'
```

`/site/health` 未注册；`/health` 与 `/api/health` 均已注册，任一可用。裸 `/health` 若走 PATH_INFO 之外的部署方式，需部署侧补一条 rewrite 指向 `api/index.php`。

## 5. 错误码处置

`code` 在 `100~599` 内同步为同名 HTTP 状态码；`4230` 越界，HTTP 保持 200。限流响应不带 `Retry-After` 头，`retry_after` 只出现在登录锁消息文本中。

| code | 典型触发 | 处置 |
| --- | --- | --- |
| 400 | 参数校验失败、业务前置不满足 | 核对 `API_接口手册.md` 的参数名与必填项 |
| 401 | JWT 缺失 / 过期 / `token_version` 不符 | 重新登录；核对 `JWT_SECRET` 与 `JWT_EXPIRE` |
| 402 | 付费模块未授权、试用配额或资源上限、余额不足 | 后台「授权管理」核对模块与档位 |
| 403 | 角色不足、账号禁用、CSRF 失败、cron token 无效 | 见第 7 节；核对 `role` 与 `X-Cron-Token` |
| 404 | 资源不存在、路由未匹配 | 核对 `api/routes.php` 是否注册；核对伪静态 |
| 409 | 状态冲突、唯一性冲突 | 刷新资源状态后重试 |
| 422 | 语义校验不通过 | 按消息修正字段内容 |
| 423 | 登录阶梯锁定 | 按消息中的分钟数等待 |
| 429 | 限流、登录锁、验证码闸 | 见第 6 节 |
| 500 | 数据库、GD、上传、认证服务异常 | 按 `error_id` 查第 2 节日志 |
| 501 | 服务端版本不满足 | 升级服务端 |
| 502 | 在线升级下载远程源码失败 | 核对 `cURL` 扩展与外网连通性 |
| 503 | 功能未启用、系统未安装 | 核对 `.installed.lock` 与功能开关 |
| 4230 | 站点模式功能守卫拦截 | HTTP 200，按 `code` 判定；后台「站点模式」开启该功能 |

| 场景 | 返回值 |
| --- | --- |
| CSRF 失败 | `403 CSRF验证失败` |
| JWT 失效 | `401 Token 已过期或无效` / `请先登录` |
| 模块未授权 | `402 该功能需要授权后才能使用（module: xxx）` |
| 功能未开启 | `4230 该功能未开启`（HTTP 200） |

## 6. 限流

| 动作 | 阈值 | 适用 |
| --- | --- | --- |
| `api_read_polling` | 2400 次 / 60 秒 | 轮询类 GET |
| `api_read` | 1500 次 / 60 秒 | 其余 GET |
| `api_write` | 600 次 / 60 秒 | POST / PUT / DELETE / PATCH |

| 项 | 值 |
| --- | --- |
| 计数键 | `rate_limit_{action}_{identity}`，`identity` = `user_{id}` 或 IP |
| 轮询前缀 | `/api/posts/check-new`、`/api/notifications/unread-count`、`/api/follow/stats`、`/api/chat/sse`、`/api/events/sse`、`/api/sse`、`/api/chat/`、`/api/notifications/` |
| 豁免 | 仅 `admin` 角色；不按私网 IP 豁免 |
| IP 解析 | `REMOTE_ADDR` 命中 `TRUSTED_PROXIES` 时才解析 `X-Forwarded-For` 最左段 |
| 超限 | HTTP 429 + `{"code":429,"message":"请求过于频繁，请稍后再试"}` |

| 独立闸门 | 阈值 |
| --- | --- |
| `check_username` / `check_email` | 10 次 / 60 秒 |
| 邮件 IP | 20 次 / 小时、60 次 / 天 |
| 手机验证码 IP | 20 次 / 小时、60 次 / 天，冷却 60 秒，TTL 300 秒 |

反代部署时把反代 IP 加入 `TRUSTED_PROXIES`，否则全部客户端会落在同一个 `REMOTE_ADDR` 上共享配额。`config.php` 的 `RATE_LIMIT_REQUESTS` / `RATE_LIMIT_WINDOW` 不作用于上述中间件分组阈值。

## 7. 鉴权与 CSRF

### 7.1 启动守卫

| 条件 | 结果 |
| --- | --- |
| `JWT_SECRET` 长度 `< 32` 或命中公开示例值 | 生产 `500` 并 `exit`，响应提示配置密钥 |
| `APP_DEBUG=true` 且未定义密钥 | 补 `dev-only` 临时值并放行 |
| `config.php` 缺失 | 整站 500 + `error_id` |
| `.installed.lock` 与 `cache/install.lock` 均不存在 | 前台 302 / API 503 |

```bash
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

把输出写入 `config.php` 的 `JWT_SECRET`，重启 PHP-FPM 后复测 `/health`。

### 7.2 CSRF 放行条件

| 条件 | 说明 |
| --- | --- |
| GET / HEAD | 直接放行；`/posts/check-new`、`/notifications`、`/auth/me` 附加 `Cache-Control: private` |
| 纯 Bearer | 有 `Authorization: Bearer` 且无会话 Cookie |
| App / 小程序 | `X-Client-Type` 精确为 `app` 或 `miniapp` 且无认证 Cookie |
| 公开路径 | 登录、注册、忘记密码、微信登录、刷新令牌、`/app/version`、`/app/config`、`/csrf`、5 个 cron 路径 |

token 来源为 `X-CSRF-Token` 头或 `csrf_token` 参数，有效期 3600 秒。会话 Cookie 名：`PHPSESSID`、`user_token`、`hublog_uid`、`remember_web`、`hublog_token`。

### 7.3 登录态

令牌存 httpOnly Cookie 或 `Authorization: Bearer`。`?token=` 查询参数仅 `GET /api/sse` 与 `GET /api/metrics` 两处支持，其余接口不读取（该参数在 access 日志中脱敏）。前端判定登录态以 `GET /auth/me` 为准。登录成功后需重新获取 CSRF token。

## 8. 上传与目录权限

| 项 | 值 |
| --- | --- |
| 目录 | `uploads/avatars/`、`uploads/images/`、`uploads/videos/`、`uploads/attachments/` |
| 分级 | 按 `年/月/日` 自动创建，`0777` |
| 单文件大小 | `UPLOAD_MAX_SIZE` = `10 * 1024 * 1024`（10 MB），超限返回 `400` |
| 图片类型 | `image/jpeg`、`image/png`、`image/gif`、`image/webp` |
| 附件扩展 | `zip rar 7z pdf doc docx xls xlsx ppt pptx txt` |
| `.htaccess` | `upload_max_filesize 100M`、`post_max_size 100M`、`max_execution_time 120` |

```bash
mkdir -p uploads/{avatars,images,videos,attachments} cache logs backups
chown -R www:www uploads cache logs backups
chmod -R 755 uploads/ cache/ logs/
```

`500 上传目录创建失败` 时检查属主与父目录写权限；`error_log('[Hublog Upload] 目录创建失败: ...')` 会给出具体路径。应用层 10 MB 限制与 `.htaccess` 的 100 MB 是两个独立阈值。

## 9. 数据库与迁移

| 症状 | 判据 / 处置 |
| --- | --- |
| `500 数据库连接失败` | 核对 `DB_HOST/PORT/NAME/USER/PASS/CHARSET`、`PDO_MySQL`、MySQL 服务 |
| 迁移未生效 | 删 `cache/.schema_verified` 后重跑；查 `/health` 的 `checks.migration` |
| `cache/.migration_failed` 存在 | 读其中 `target_version` / `error` / `time`，按错误修复后删标记 |
| 表 / 列缺失 | 跑 `php scripts/build_migration_contract.php --check`；不一致用 `--write` 重生成契约 |
| 计数不准 | `php bin/reconcile-counters.php` |

| 对账列 | 来源 |
| --- | --- |
| `posts.comment_count` | `comments.post_id` |
| `posts.like_count` | `likes.post_id` |
| `circles.member_count` | `circle_members.circle_id` |
| `circles.post_count` | `posts.circle_id` |

DDL 的 `try/catch` 不抛异常，迁移末尾的终态契约自检是唯一兜底；新增迁移后必须跑契约生成与 `php api/tests/run_tests.php`。

## 11. 备份与恢复

| 项 | 值 |
| --- | --- |
| 目录 | `backups/`，运行时自动创建 |
| 命名 | `hublog_db_Ymd_His.sql`、`hublog_code_Ymd_His.zip` |
| 索引 | `backups/index.json`，字段 `timestamp` / `created_at` / `db_backup` / `code_backup` / `upgrade` |
| 保留 | 升级备份最近 2 次 |
| 排除目录 | `uploads`、`cache`、`logs`、`backups`、`.git`、`.DS_Store`、`license_system/data` |
| 排除文件 | `config.php`、`.env`、`.htpasswd` |
| 覆盖时受保护 | `config.php`、`.env`、`uploads/`、`cache/`、`logs/`、`backups/` |

数据库备份由 `SHOW TABLES` + `SHOW CREATE TABLE` + `SELECT *` 生成，含 `SET FOREIGN_KEY_CHECKS=0/1`。`sql/hublog.sql` 只是初始化引导脚本，不是备份。

| 后台导出 | 值 |
| --- | --- |
| 接口 | `GET /api/admin/export` |
| `type` | `users`（默认）/ `posts` / `comments` / `all` |
| `format` | `json`（默认）/ `csv`；非 `csv` 一律按 JSON 输出 |
| 文件名 | `hublog_<type>_<Y-m-d>.json` / `.csv`，CSV 带 UTF-8 BOM |

回滚顺序固定为**先恢复数据库、后恢复代码**：

| 步骤 | 操作 |
| --- | --- |
| 1 | 核对 `backups/index.json` 中目标记录的两个文件都存在 |
| 2 | 后台 `POST /api/admin/rollback`，或升级失败时自动回滚 |
| 3 | `restoreDatabase()` 整段执行 SQL，随后 `restoreFiles()` 解压代码包 |
| 4 | 清 `cache/*.cache`，复测 `/health` |

`404 没有找到升级备份` 表示索引中无 `upgrade` 非空的记录；`500 备份文件缺失，无法回滚` 表示两个备份文件之一不存在。

## 12. 脚本清单

| 命令 | 作用 |
