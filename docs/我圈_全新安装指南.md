## 1. 安装前必须知道的三件事

### 1.1 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| PHP | >= 8.0，推荐 8.1 | 安装向导会检测版本，低于 8.0 直接拦下 |
| PHP 扩展 | 必需 `PDO`、`PDO_MySQL`、`GD`、`JSON` | 缺一个都点不动"下一步" |
| PHP 扩展 | 推荐 `Fileinfo`、`Redis`、`cURL` | `Fileinfo` 缺失只降级上传校验，不阻断；`Redis` 用于缓存加速；`cURL` 用于在线升级 |
| MySQL | >= 5.7，库字符集 `utf8mb4` | 向导会自动建库并统一字符集，不需要你先建表 |
| Web 服务器 | Nginx / Caddy 2 / Apache / IIS 任选其一 | 仓库自带四套配置，见 [第 5 节](#5-按环境安装自己管服务器无面板) |
| 可选依赖 | FFmpeg（视频转码）、Redis（缓存加速）、Ollama（本地 AI） | 不装不影响安装和基本使用 |

安装向导会自动检测并（尝试）创建以下 8 个目录，只要站点根目录可写即可：`uploads/`、`uploads/avatars/`、`uploads/images/`、`uploads/videos/`、`uploads/attachments/`、`cache/`、`logs/`、`backups/`。

### 1.2 第一件大事：先安装，后加安全规则

仓库自带的 `nginx.conf`、`.htaccess`、`Caddyfile`、`web.config` 里，都有一条安全规则把 `install.php` 判为敏感文件并拒绝访问（Nginx / Caddy / IIS 返回 404，Apache 返回 403）。**这是故意的**——装完后 `install.php` 必须封死，否则安装请求可被重放。

但这带来一个顺序问题：

> **正确顺序：先让 `install.php` 能访问 → 跑完安装向导 → 再把安全配置放上去。**
>
> 如果你一上来就把仓库的 `nginx.conf` / `.htaccess` / `Caddyfile` / `web.config` 全部生效，再访问 `/install.php` 会被拒绝（404 或 403），安装向导根本打不开。

各环境的处理办法：

| 环境 | 安装阶段怎么做 | 装完后怎么做 |
| --- | --- | --- |
| 宝塔面板 | 先不要贴伪静态；默认站点配置即可访问 `install.php` | 装完再到"伪静态"粘贴 `nginx.conf` 的伪静态区 |
| 独立 Nginx | 先只放最简 server 块（见 [5.1](#51-nginx)），不要贴敏感文件规则 | 装完再用完整 `nginx.conf` 替换并 `nginx -t` 重载 |
| Apache / IIS | 先把根目录 `.htaccess` / `web.config` 临时改名为 `.htaccess.bak` / `web.config.bak` | 装完再改回原名 |
| Caddy | 先用只含 `root` + `php_fastcgi` 的最简 Caddyfile | 装完再换成仓库完整 `Caddyfile` |
| 共享虚拟空间 | 通常已提供面板自带的重写，先看 [第 4 节](#4-按环境安装只有虚拟空间无服务器权限) | 装完后按面板能力尽量补上防护 |

### 1.3 第二件大事：不要用 `cp config.example.php config.php` 的方式"手工配置"

`config.example.php` 只是示例，`JWT_SECRET` 是空值。而源码 `bootstrap.php::assertJwtSecret()` 会拒绝空密钥启动。

**正确做法：什么都不用改，直接跑 `install.php` 向导**，它会自己生成 `config.php`（权限 `0600`）、随机 32 字节 `JWT_SECRET`、建表、写入默认配置。手工复制示例文件反而会导致启动失败。

### 1.4 第三件大事：装完 `install.php` 会自己删除

向导成功后会 `unlink(__FILE__)` 自删 `install.php`，并生成根目录 `.installed.lock` 作为"已安装"的唯一凭据。若因权限不足没删掉，页面会提示你手动删除——**一定要删**，否则任何人都能重放安装请求。

## 2. 零基础：先看这两种最简单的装法

### 2.1 完全本地试用（一台普通电脑，不买服务器）

适合：只想先看看系统长什么样、点一点功能。

用 PHP 自带的临时服务器，不需要装 Nginx / Apache：

```bash
# 1. 下载/克隆代码（用 Git，或在仓库页面下载 ZIP 解压）
git clone https://gitee.com/aiwoquan/woquan.git
cd woquan

# 2. 起临时站点（PHP >= 8.0，且 PDO/PDO_MySQL/GD/JSON 扩展已开）
php -S 127.0.0.1:8899 -t .
```

浏览器打开 <http://127.0.0.1:8899/install.php>，按 [第 7 节](#7-安装向导每一步怎么填) 填表即可。数据库填本机 MySQL 的连接信息；本机没装 MySQL 的话，用 `localhost` / `root` / 你的本机密码，向导会自己建库。

> 这个临时服务器只能本机访问，关掉命令行窗口就停了，仅用于试用。正式对外服务用后面章节的方案。

### 2.2 宝塔面板（国内最常用，新手最省事）

适合：刚买了一台云服务器（阿里云 / 腾讯云 / 华为云等），或准备买。

1. **装面板**：按服务器厂商文档装宝塔面板（Linux 版）。装好后浏览器进入面板，记下面板地址、账号密码。
2. **装软件**：面板 →「软件商店」→ 安装 **Nginx**、**MySQL 5.7 或 8.0**、**PHP 8.1**。
3. **装 PHP 扩展**：面板 →「软件商店」→ 已装 PHP 8.1 →「设置」→「安装扩展」，勾上 `pdo_mysql`、`gd`（`fileinfo` 建议也装）。宝塔默认一般已带 `pdo`、`json`。
4. **建站点**：面板 →「网站」→「添加站点」，填你的域名（没有域名先填服务器 IP 也能访问），根目录保持默认（如 `/www/wwwroot/你的域名`）。这一步会自动创建数据库，记下**数据库名、用户名、密码**（后面向导要用）。
5. **上传代码**：面板 →「文件」→ 进入站点根目录 → 上传仓库 ZIP → 在线解压，让 `index.php`、`install.php`、`api/`、`admin/` 等直接位于站点根目录（**不要**多套一层 `woquan/` 目录）。也可用 FTP 上传，见 [4.2](#42-用-ftp-上传代码)。
6. **设置运行目录 / 伪静态**：安装阶段**先不要贴伪静态**。"设置 → 基本配置"里 PHP 版本选 8.1。
7. **跑安装向导**：浏览器打开 `http://你的域名/install.php`，按 [第 7 节](#7-安装向导每一步怎么填) 填表。数据库填第 4 步记下的信息。
8. **装完再贴伪静态**：安装成功后，面板 →「网站」→ 你的站点 →「伪静态」，把仓库 `nginx.conf` 里"伪静态区（宝塔粘贴：从这一行开始）"到"（到这一行结束）"之间的整段复制进去，保存。
   - 只粘伪静态区，不要粘文件末尾被注释掉的 `location ~ \.php` 块——宝塔自带 PHP 块，重复会报 `duplicate location`。
   - 旧规则目录（如 `D:\BtSoft\nginx\conf\rewrite\xxx\`）里如果有以前手写的 `.conf`，要先清空，否则同样冲突。
   - 宝塔自带的 PHP 配置已支持 PATH_INFO，默认 `url_rewrite=0` 即可，不用改。
9. **验证**：浏览器打开域名首页和 `/admin/index.html`，按 [第 8 节](#8-装完怎么验证装对了) 检查。

> 宝塔 Windows 版步骤相同，只是路径形如 `D:\BtSoft\wwwroot\...`，PHP 管理界面位置略有差异。

## 3. 按环境安装：云服务器 + 面板

这一节讲各种"面板"环境。流程都是同一套：

1. 面板里装好 PHP 8.0+ 和 MySQL 5.7+，并开启必需扩展；
2. 建站点 + 建数据库（记下库名/账号/密码）；
3. 把代码传到站点根目录（`index.php` 和 `install.php` 必须在根）；
4. 先让 `install.php` 能访问，跑向导；
5. 装完后再把重写/安全规则补上。

下面按面板给出具体入口。

### 3.1 阿里云 / 腾讯云轻量应用服务器

这两家的"轻量应用服务器"常提供**预装宝塔镜像**的应用模板——如果你选的就是宝塔镜像，直接看 [2.2](#22-宝塔面板国内最常用新手最省事)。

如果选的是纯系统镜像（Ubuntu / CentOS）：

- 想省事：自己装宝塔后按 [2.2](#22-宝塔面板国内最常用新手最省事)。
- 不想装面板：按 [第 5 节](#5-按环境安装自己管服务器无面板) 的独立 Nginx 方案。
- 云主机的**安全组/防火墙**要放行 80（HTTP）和 443（HTTPS）端口，否则浏览器打不开站点。

### 3.2 cPanel（海外主机最常见）

1. 登录 cPanel →「Software」→「Select PHP Version」→ 选 PHP 8.0/8.1，勾选 `pdo_mysql`、`gd`、`fileinfo`。
2. cPanel →「MySQL Databases」→ 新建数据库和数据库用户，把用户加入数据库并勾「ALL PRIVILEGES」，记下库名/用户/密码。
3. cPanel →「File Manager」→ 进入 `public_html`（或你的站点根）→ 上传仓库 ZIP 并解压，让 `install.php` 位于该目录。
4. **先确认 cPanel 的图片优化/热链保护等插件没有拦截 `install.php`**；若访问 404，用文件管理器临时把 `.htaccess` 改名。
5. 浏览器打开 `https://你的域名/install.php` 跑向导。
6. 装完后把 `.htaccess` 改回，确认站点首页、API 正常。

### 3.3 DirectAdmin

1. 「User Level」→「Domain Setup / PHP Version Selection」选 PHP 8.1；在 php.ini 自定义里确认 `pdo_mysql`、`gd`、`fileinfo` 已开。
2. 「MySQL Management」→ 建库和带全部权限的用户。
3. 用「File Manager」把代码传到 `domains/你的域名/public_html`。
4. 浏览器打开 `/install.php` 跑向导；装完后确认 `.htaccess` 生效。

### 3.4 Plesk

1. Plesk → 站点 →「PHP 设置」→ PHP 版本选 8.1，扩展勾选 `pdo_mysql`、`gd`、`fileinfo`。
2. 「数据库」→ 新建 MySQL 库与用户，记下凭据。
3. 「文件管理器」上传代码到 `httpdocs/`（`install.php` 必须在根）。
4. 访问 `/install.php` 完成安装；Plesk 的 nginx 缓存规则可能影响后台静态资源，装完后如后台空白，按[运维排障手册](./运维排障手册.md)排查缓存。

### 3.5 其他面板（AMH、WDCP、1Panel、宝塔 Windows 等）

按你的面板找到对应四项：**PHP 版本与扩展、MySQL 库与用户、站点根目录、伪静态设置**，然后照 [第 3 节](#3-按环境安装云服务器--面板) 的通用五步走。

关键提醒：

- 面板的"运行目录"若可设置，指向站点根目录（有 `index.php` 的那层），不要指向 `public/` 之类不存在的目录。
- 伪静态在安装阶段先留空，装完再按 [5.1](#51-nginx) 或 [5.3](#53-apache) 补。
- 面板自带的"防跨站 / 目录隔离"若把 `uploads/`、`cache/`、`logs/`、`backups/` 排除在可写范围外，要在面板里给这些目录写权限，否则安装检测过不了。

## 4. 按环境安装：只有虚拟空间（无服务器权限）

适合：买的是共享虚拟主机 / 虚拟空间，只能通过 FTP 和主机商控制面板操作，**没有 SSH、不能改 Nginx、不能装系统软件**。

### 4.1 先确认：你的空间能不能装

| 必查项 | 不满足的后果 | 怎么查 |
| --- | --- | --- |
| PHP >= 8.0 | 安装向导第一步就过不去 | 主机控制面板一般显示 PHP 版本；或上传 `phpinfo.php` 查看 |
| `pdo_mysql`、`gd`、`json`、`pdo` 扩展 | 安装向导拦下 | 用 `phpinfo()` 搜扩展名；不支持自定义 PHP 的空间通常装不了 |
| MySQL >= 5.7 且能建表 | 安装失败 | 控制面板看 MySQL 版本；确认数据库用户有建表权限 |
| 支持 `.htaccess`（Apache）或等效重写 | 前台/API 路由不通 | 问主机商是否支持 `.htaccess` 覆盖（`AllowOverride All`） |
| 站点根目录可写 | `config.php` 写不进去，装不了 | 装完看向导检测；空间通常会给根目录写权限 |

> **不支持 PHP 8.0、不支持 `pdo_mysql`、或不能改 `php.ini`/`.htaccess` 的超廉价空间，无法安装本系统。** 遇到这种情况只能换主机商或升级套餐。

### 4.2 用 FTP 上传代码

1. 在仓库页面点「克隆/下载」→「下载 ZIP」，得到后端源码压缩包。
2. 解压到本地，确认第一层就能看到 `index.php`、`install.php`、`api/`、`admin/`、`templates/`。
3. 用 FTP 客户端（FileZilla 等）连接主机商给的 FTP 地址/账号/密码，**以二进制模式**上传全部文件到站点根目录（常叫 `public_html`、`htdocs`、`wwwroot`、`web`）。
4. 上传后在主机控制面板确认 PHP 版本为 8.0+。

> 如果空间提供"在线解压"，直接上传 ZIP 再解压更省事，但注意解压后文件必须落在站点根目录，不能多套一层目录。

### 4.3 虚拟空间的 `.htaccess` 顺序

仓库根目录的 `.htaccess` 会封 `install.php`（见 [1.2](#12-第一件大事先安装后加安全规则)）。所以：

1. 上传后先用 FTP 把根目录 `.htaccess` 改名为 `.htaccess.bak`（暂时不生效）。
2. 浏览器打开 `https://你的域名/install.php`，跑向导。
3. 装完立刻把 `.htaccess.bak` 改回 `.htaccess`，恢复路由和安全防护。
4. 打开首页和 `/api/site/config` 验证；若 404，说明空间没启用 `.htaccess` 覆盖，联系主机商开启。

> 部分空间提供"伪静态"面板而不是直接改 `.htaccess`。这类空间请在面板里选 Nginx/Apache 伪静态模板，或把 `.htaccess` 的重写段交给主机商协助导入。

### 4.4 虚拟空间的已知限制

- **没有 SSH**：不能用命令行，`php -S`、cron 命令、Redis/FFmpeg 都装不了。
- **定时任务受限**：[运维排障手册](./运维排障手册.md)第 10 节的 5 个 cron 需要主机控制面板支持"定时 URL 唤醒"才能实现；没有的话，定时发布、计数对账等不会自动跑。
- **PATH_INFO 可能缺失**：源码 `Router::resolvePath()` 与前台 `index.php` 都做了从 `REQUEST_URI` 剥离脚本名的兜底，所以只要重写规则把请求转到 `index.php` / `api/index.php`，即使没有 PATH_INFO 也能工作。默认保持 `url_rewrite=0`，不要开伪静态。
- **在线升级可能受限**：升级包上传依赖 `Fileinfo` 和足够的上传体积，廉价空间常卡在这里，建议在面板里调大 `upload_max_filesize` / `post_max_size`（仓库配置对齐的是 100MB）。

## 5. 按环境安装：自己管服务器（无面板）

这一节给有 SSH、自己配 Web 服务器的场景。四套配置都随仓库提供，按服务器类型选一套。

通用前置步骤（四套都一样）：

```bash
# 1. 放代码到站点根目录
git clone https://gitee.com/aiwoquan/woquan.git /var/www/woquan
cd /var/www/woquan

# 2. 建目录并给 Web 用户写权限（Web 用户按实际调整，Debian/Ubuntu 是 www-data，CentOS 是 apache/www）
mkdir -p uploads/{avatars,images,videos,attachments} cache logs backups
chown -R www-data:www-data uploads cache logs backups
chmod -R 755 uploads cache logs backups

# 3. MySQL 建空库（不用建表，向导会建）
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS hublog CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

> **注意顺序**：第 3 步建空库是可选的——向导会自己 `CREATE DATABASE`。若你的 MySQL 用户有建库权限，可跳过手工建库；手工建库时别导入任何 SQL 文件。

### 5.1 Nginx

1. 安装 Nginx 与 PHP-FPM 8.1（`pdo_mysql`、`gd`、`fileinfo` 扩展）。
2. **安装阶段**用最简 server 块，让 `install.php` 可访问：

```nginx
server {
    listen 80;
    server_name 你的域名;
    root /var/www/woquan;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }
    location /api/ {
        try_files $uri /api/index.php?$query_string;
    }
    location ~ \.php(/|$) {
        fastcgi_split_path_info ^(.+?\.php)(/.*)$;
        fastcgi_pass 127.0.0.1:9000;   # 按实际改成 unix:/run/php/php8.1-fpm.sock
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_param PATH_INFO $fastcgi_path_info;
        include fastcgi_params;
    }
}
```

3. `nginx -t` 通过后重载，浏览器打开 `/install.php` 完成向导。
4. **装完后**：把仓库 `nginx.conf` 的全部内容按注释说明并入 server 块（敏感文件拒绝、缓存策略、健康检查 `/health` 转交等），把上面最简块里的 `location ~ \.php` 删掉避免重复，`nginx -t && nginx -s reload`。
5. 独立 Nginx 的 `location = /health` 不能省，否则 `/health` 会落到前台入口返回首页 HTML 而不是 JSON。

### 5.2 Caddy 2

1. **安装阶段**用最简 Caddyfile（域名换成你的）：

```caddyfile
你的域名 {
    root * /var/www/woquan
    php_fastcgi unix//run/php/php8.1-fpm.sock
    file_server
}
```

2. `caddy validate` 通过后重载，访问 `/install.php` 完成向导。
3. **装完后**换成仓库完整 `Caddyfile`：改根路径与域名，保留 `@sensitive`（封 `install.php`）、`@internal`、静态资源缓存规则。

### 5.3 Apache

1. 安装 Apache + PHP 8.1 模块（`pdo_mysql`、`gd`、`fileinfo`），启用 `mod_rewrite`、`mod_headers`。
2. **安装阶段**先把仓库根目录 `.htaccess` 临时改名（见 [1.2](#12-第一件大事先安装后加安全规则)），VirtualHost 里给站点目录 `AllowOverride All`。
3. 访问 `/install.php` 完成向导。
4. **装完后**把 `.htaccess` 改回原名，确认路由和后台静态资源正常。

> `.htaccess` 已包含 API、后台、`/health`、`/robots.txt`、`/sitemap.xml` 的重写与敏感文件拒绝，不需要另写规则。

### 5.4 IIS（Windows Server）

1. 安装 IIS + PHP 8.1（FastCGI 模式），开启 `pdo_mysql`、`gd`、`fileinfo`。
2. **安装阶段**先把根目录 `web.config` 临时改名为 `web.config.bak`。
3. 访问 `/install.php` 完成向导。
4. **装完后**改回 `web.config`，确认重写模块（URL Rewrite）已安装并生效。

### 5.5 PATH_INFO 与伪静态的关系（别纠结）

系统默认 `url_rewrite=0`，走 **PATH_INFO 模式**，形如 `/index.php/search`、`/api/index.php/auth/login`。这套模式不依赖 Web 服务器的重写规则，最不容易出问题。

- 四套配置只为让 `/search`、`/api/auth/login` 这类"好看的 URL"也能用，属于锦上添花。
- 装完发现某些页面 404，先确认默认模式能用；只有确认重写规则配好了，才在后台「站点设置」把 `url_rewrite` 打开。
- 源码入口对 PATH_INFO 缺失做了兜底：即使服务器不填充 `$_SERVER['PATH_INFO']`，也会从 `REQUEST_URI` 剥离脚本名正确路由。

## 6. 按环境安装：Windows / macOS 本地开发

### 6.1 Windows：phpStudy（小皮面板）/ XAMPP / WampServer

1. 装面板后启动 **Apache 或 Nginx + PHP 8.1**，并在面板里勾选 `pdo_mysql`、`gd`、`fileinfo` 扩展；启动 MySQL。
2. 面板里建站点（或把代码放进 `www` / `htdocs` 目录），让 `install.php` 位于站点根。
3. 若用 Apache 且根目录已带 `.htaccess`，安装阶段先改名；用 Nginx 就先贴 [5.1](#51-nginx) 的最简块。
4. 浏览器打开 `http://localhost/install.php` 跑向导。
5. 装完恢复 `.htaccess` / 完整 Nginx 配置。

### 6.2 macOS：MAMP / 自带 PHP

- MAMP：把 PHP 版本设为 8.1，代码放进 `htdocs`，用面板建 MySQL 库，访问 `localhost:8888/install.php`。
- 系统自带 PHP 若 >= 8.0 且扩展齐全，用 [2.1](#21-完全本地试用一台普通电脑不买服务器) 的 `php -S` 方式最快。

### 6.3 Docker（进阶，可选）

> 仓库**没有**官方 Dockerfile 或 docker-compose 文件，下面是自己起一个 PHP 8.1 + Apache 容器的通用做法，仅作参考；镜像扩展、卷挂载按你本机实际调整。

```bash
# 起一个带 pdo_mysql/gd 的 PHP 8.1 Apache 容器，把当前目录挂到站点根
docker run -d --name woquan -p 8080:80 \
  -v "$PWD":/var/www/html \
  php:8.1-apache \
  sh -c "docker-php-ext-install pdo_mysql gd && a2enmod rewrite && apache2-foreground"
```

然后访问 <http://localhost:8080/install.php>。数据库用另一容器或宿主机 MySQL，数据库主机填容器能访问到的地址（不是 `localhost`，容器里的 `localhost` 指容器自己）。装完后把 `.htaccess` 恢复原名。

## 7. 安装向导：每一步怎么填

浏览器访问 `https://你的域名/install.php`（本地则是 `http://127.0.0.1:8899/install.php`），共三步。

### 第一步：环境检测

逐项确认 PHP 版本、扩展、目录权限均为"通过/已安装/可写"：

- `Fileinfo` 显示"未安装(可继续)"是**正常的**，只影响上传校验强度，不影响安装。
- 任何必需项失败，按钮会灰掉，必须修复后再点"下一步：配置数据库"。
- 目录权限失败：回到服务器/面板给对应目录写权限（见各环境章节）。

### 第二步：数据库配置

| 字段 | 怎么填 | 约束（填错会被拦） |
| --- | --- | --- |
| 数据库主机 | 同机填 `localhost`；面板给的可能是 `127.0.0.1` 或 `localhost` | 字母、数字、点、下划线、连字符、冒号 |
| 数据库端口 | 一般 `3306` | 1 - 65535 的整数 |
| 数据库名称 | 面板里记下的库名 | 只能字母、数字、下划线 |
| 数据库用户名 | 面板里记下的用户名 | — |
| 数据库密码 | 面板里记下的密码 | — |
| 站点名称 | 你的站点名，如「我圈」 | 不超过 100 字符 |
| 管理员账号 | 你自己的后台登录名，如 `admin` | 字母开头，2 - 20 位字母/数字/下划线 |
| 管理员密码 | 自己设一个强密码 | 至少 8 位，建议大小写 + 数字 + 符号 |
| 确认密码 | 再输一遍 | 必须与上一致 |

点"开始安装"后，向导在背后依次做了这些事（无需你干预）：

1. 校验安装 Token 与请求来源，防止跨站重放；
2. 用你填的账号连 MySQL，创建数据库（若不存在）并统一为 `utf8mb4 / utf8mb4_unicode_ci`；
3. **预检**：如果目标库已有管理员账号，直接拒绝安装，不会覆盖你的配置和密码；
4. 生成 `config.php`（权限 `0600`）和随机 32 字节 `JWT_SECRET`；
5. 执行 Migration 一次性建好全部表和默认配置（**不需要手工导入 `sql/hublog.sql`**，那个脚本只是初始化引导）；
6. 创建管理员（id = 1）和内置 AI 助手账号（id = 2）；
7. 写根目录 `.installed.lock`，并尝试自删 `install.php`。

### 第三步：安装完成

看到"安装成功"即完成。若提示"`install.php` 未自动删除"，登录后台后手动删除根目录的 `install.php`。

> 如果看到"目标数据库已存在管理员账号……已拒绝本次安装"，说明这个库之前装过。**不要反复点安装**——先按 [搬家迁移指南](./我圈_搬家迁移指南.md) 备份，确认是否要重装。

## 8. 装完怎么验证装对了

### 8.1 浏览器直接看

| 检查项 | 期望 |
| --- | --- |
| 前台首页 `/` | 显示首页，站点名是你在向导里填的值 |
| 后台 `/admin/index.html` | 打开登录页，用向导里填的管理员账号密码能登录 |
| `https://你的域名/health` | 返回一段 JSON，其中 `data.status` 为 `ok` |

`/health` 正常返回示例（HTTP 状态码始终是 200，**必须读 `data.status` 判断**）：

```json
{"code":200,"message":"success","data":{"status":"ok","time":"2026-11-23T09:00:00+08:00","checks":{"db":{"status":"ok","detail":"connected"},"cache":{"status":"ok","detail":"file"},"disk":{"status":"ok","detail":"85.2% free"},"migration":{"status":"ok","detail":"no recent failure"}}}}
```

### 8.2 命令行验证（有 SSH 时）

```bash
curl -s https://你的域名/health | php -r '$j=json_decode(stream_get_contents(STDIN),true); echo $j["data"]["status"], PHP_EOL;'
```

期望输出 `ok`。若输出 `degraded` 或 `down`，见[运维排障手册](./运维排障手册.md)。

裸 `/health` 若返回首页 HTML，改用 `/api/health`（两条路由都已注册），并检查 Web 服务器重写规则——独立 Nginx 需要 `location = /health` 那条转交 API 入口。

### 8.3 两个"装完立刻要做"的动作

1. 确认 `install.php` 已删除、`config.php` 权限为 `0600`、`.installed.lock` 不能被浏览器直接访问（访问应 404）。
2. 按 [1.2](#12-第一件大事先安装后加安全规则) 恢复完整安全配置（伪静态 / `.htaccess` / `Caddyfile` / `web.config`）。

## 9. 装完之后的必做配置

1. **站点模式与外观**：后台「站点设置」选择站点模式（`social` / `blog` / `news` / `content` / `custom`），再到「主题管理」切换外观。模式会同时影响后台菜单与前台帖子类型、工具栏和导航，详见[后台管理使用手册](./后台管理使用手册.md)。
2. **站点地址**：补填 `site_url`，配置分页与 SEO 时按实际域名设置；按需填写 `seo_robots_txt`。
3. **定时任务**：后台「站点设置」配置 `cron_secret`，按[运维排障手册](./运维排障手册.md)第 10 节添加 5 个 cron 与计数对账任务。共享空间没有 cron 的见 [4.4](#44-虚拟空间的已知限制)。
4. **缓存与代理**：高并发站点把 `CACHE_DRIVER` 切到 `redis`（需装 Redis 扩展）；反向代理后填写 `TRUSTED_PROXIES`。
5. **商业化**：需要使用付费圈子、内容付费、钱包与会员时，在后台「授权管理」确认模块与档位。
6. **备份**：确认 `backups/` 可写，升级前会自动生成数据库与代码备份。

安全加固（生产环境）：

- 保持 `APP_ENV=production`、`APP_DEBUG=false`；
- 把 `CORS_ALLOWED_ORIGINS` 从默认的 `*` 改为实际域名白名单；
- 不要把 `?token=` 作为常规鉴权方式，仅 SSE 与指标接口读取该参数；
- 完整策略与漏洞报告方式见仓库根目录 [SECURITY.md](../SECURITY.md)。

## 10. 安装失败怎么办

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `/install.php` 显示 404 / 403 | 安全配置把安装脚本封了 | 按 [1.2](#12-第一件大事先安装后加安全规则) 临时移走 `.htaccess` / `web.config`，或先别贴伪静态 |
| 打开首页直接跳到 `install.php` 或 API 返回 503 | 还没装或 `.installed.lock` 不在根目录 | 完成向导；确认锁文件在站点根目录 |
| 环境检测扩展失败 | PHP 扩展没开 | 面板/php.ini 开启 `pdo`、`pdo_mysql`、`gd`、`json` 并重启 PHP-FPM |
| 目录不可写 | 属主/权限不对 | `chown -R www-data:www-data uploads cache logs backups`（Web 用户按实际改） |
| 数据库连接失败 | 凭据或主机填错 | 核对库名/用户/密码；容器里别填 `localhost`；确认 MySQL 服务在跑 |
| 提示"数据库名只能包含字母、数字和下划线" | 库名带了连字符等 | 改用纯字母数字下划线 |
| 提示"目标数据库已存在管理员账号" | 重放安装请求 | 先备份，确认是否重装；不要反复提交 |
| 提示"已安装" | 根目录有 `.installed.lock`（或旧版 `cache/install.lock`） | 确认是不是要重装；重装前先备份数据 |
| 前台 302 / API 503 | 安装锁不存在，或锁文件位置不对 | 重新跑向导；锁必须在站点根目录 |
| 首页能开、点链接 404 | 伪静态没配或 PATH_INFO 被关 | 保持 `url_rewrite=0`，按 [5.5](#55-path_info-与伪静态的关系别纠结) 配重写 |
| `/health` 返回首页 HTML | 请求落到前台入口了 | 独立 Nginx 补 `location = /health`；或改用 `/api/health` |
| 迁移未生效 | 迁移失败留下标记 | 看 `/health` 的 `checks.migration` 与 `cache/.migration_failed`，详见[运维排障手册](./运维排障手册.md)第 9 节 |
| 后台页面空白 / 菜单点不动 | 新旧 JS 混搭缓存 | 清浏览器缓存；确认后台静态资源 `Cache-Control: no-cache` 规则生效 |
| Java/前端构建相关错误 | — | 后端不需要 Node/Composer 构建，`vendor/` 只用于开发测试，生产可不装 |

## 11. 术语小抄

| 名词 | 白话解释 |
| --- | --- |
| 域名 | 别人访问你站点用的网址，如 `example.com` |
| 站点根目录 | 网站文件最外层目录；`index.php`、`install.php` 必须直接放在这里 |
| 数据库 | 存帖子、用户、配置的地方；用户名/密码由面板或主机商提供 |
| PHP 扩展 | PHP 的插件，缺了连不上数据库或处理不了图片 |
| 面板 | 图形化管理服务器的网页工具（宝塔、cPanel 等），不用敲命令 |
| 虚拟空间 | 多人共用一台服务器的廉价主机，通常只有 FTP 和简单控制面板 |
| PATH_INFO | 一种 URL 形式，如 `/index.php/search`；系统默认用它，不依赖伪静态 |
| 伪静态 / 重写规则 | 让 `/search` 这样的短网址转发到 `index.php` 的配置 |
| FTP | 传文件到服务器的工具，常用于虚拟空间 |
