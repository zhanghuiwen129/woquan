# 我圈 后台管理使用手册

## 1 访问与登录

| 项 | 值 |
| --- | --- |
| 入口 | `/admin/`（重写到 `admin/index.html`） |
| 后台接口前缀 | `/api/index.php/admin/...`；本手册表格内简写为 `/admin/...` |
| 登录态 | 前台登录取得的 JWT，`Authorization: Bearer` 或 httpOnly Cookie `hublog_token` |
| 登录态确认 | `GET /api/auth/me` |
| 接口中间件 | `RateLimitMiddleware`、`AuthMiddleware`、`CsrfMiddleware`、`AdminMiddleware`、`LicenseMiddleware` |

| 账号类型 | 后台范围 |
| --- | --- |
| `admin` | 全部 32 个页面 |
| 圈主（`is_circle_owner`） | 仅「活动管理」，接口仅放行 `/admin/activities`、`/admin/my-circles` |
| `user` / `reviewer` | 重定向前台 |

| 接口返回 | 条件 |
| --- | --- |
| 401「请先登录」 | 无 token |
| 401「登录状态已失效，请重新登录」 | `token_version` 不符 |
| 403「账号异常，无法操作」 | `status != 1` |
| 403「权限不足」 | 非 admin 或非圈主越权 |

前台登录入口：`POST /api/auth/login`、`/api/auth/login-phone`、`/api/auth/wx-mini-login`、`/api/app/auth/wx-app-login`。

## 3 系统设置

### 3.1 读写接口

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 读取 | `GET /admin/settings` | 返回扁平 `key => value` 映射，附加 `module_catalog`；敏感值以 `******HUBLOG_SENSITIVE_MASKED:<key>` 占位 |

| 保存外观 | `PUT /admin/theme-options` | 按主题 `settings.json` 的 `optionsSchema` 校验 |

## 4 功能开关与下发

新增或调整开关需同步三处，缺一处会导致后台可配但前台不生效。

| # | 位置 | 作用 |
| --- | --- | --- |
| 1 | `AdminSettingsController::settings()` | `$allowed` 白名单，决定后台能否保存 |
| 2 | `AppController::config()` | 下发到 App / 前台 |
| 3 | `PostCrudTrait::create()`、`PostSettingsTrait` 权限辅助 | `create()` 与权限辅助的兜底校验 |

| `$allowed` 键 | `config()` 下发键 | 兜底位置 |
| --- | --- | --- |
| `allow_register` | `register_open` | 登录注册流程 |
| `allow_post` | — | `checkUserPermission('allow_post')` |
| `allow_like` / `allow_comment` | — | `PostCommentTrait` |
| `allow_location` | `allow_location` | `PostCrudTrait` |
| `allow_mention` | `allow_mention` | `PostCrudTrait` |
| `allow_anonymous_post` | `gateMap['anonymous']` | `PostCrudTrait` |
| `allow_circle` | `allow_circle` | 圈子发布流程 |
| `allow_upload_image` / `_video` / `_attachment` | `gateMap['image'|'video'|'attachment']` | `PostUploadTrait` |
| `post_max_length` 与 `upload_max_*` | `limits.*` | `PostCrudTrait` |
| `title_required` / `category_required` | `limits.*` | `PostCrudTrait` |
| `post_types` / `post_tools` | `post_types` / `post_tools` | `isPostTypeEnabled()` |
| `site_mode` / `module_flags` / `feature_guard_mode` | `FeatureFlags::publicPayload()` | `FeatureGuardMiddleware` |

站点模式由 `saveSiteMode()` 落 `module_flags` JSON、反查 `site_mode` 并写 `feature_guard_mode`。

### 4.1 站点模式与模块预设

后台「系统设置 → 功能开关」顶部有独立「站点模式」卡片（`admin/pages/settings.html`），真值源为 `api/core/ModuleCatalog.php`（后台只渲染，不硬编码）。

| 模式 | 说明 | 开启的模块 |
| --- | --- | --- |
| social | 社交模式，全部模块开启 | 15 个模块全开 |
| blog | 博客模式，纯内容站 | `comments`、`friend_links`、`reports`、`appeals`、`safety_filter` |
| news | 资讯模式，内容 + 话题 / 精华运营 | blog 基础上加 `topics`、`featured` |
| content | 内容商业化，单篇买断 / 专栏订阅变现 | news 基础上加 `finance`、`contentpay` |

`custom`（自定义）是手动微调后的状态，不是预设；切换预设还会套用前台帖子类型 / 发布页工具栏 / 底部导航（`FRONTEND_PRESETS`）。切换只改开关、不删数据。

15 个可关模块（`ModuleCatalog::MODULES`）：`comments`、`topics`、`featured`、`friend_links`、`circles`、`chat`、`activities`、`badges`、`realname`、`reports`、`appeals`、`shop`、`finance`、`contentpay`、`safety_filter`。依赖：`appeals` 依赖 `reports`，`shop`、`contentpay` 依赖 `finance`。`ALWAYS_ON_PAGES` 的 13 页（`dashboard`、`users`、`posts`、`categories`、`attachments`、`settings`、`stats`、`export`、`plugins`、`license`、`upgrade`、`app-versions`、`crash-logs`）任何模式下都保留。

三层关系共用同一份模块注册表：

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 数据层 | `saveSiteMode()` 写 `site_mode`、`module_flags`（JSON）、`feature_guard_mode` | 开关落库，并校验依赖 |
| 菜单过滤 | `ModuleCatalog::pageMap()`（经 `FeatureFlags::publicPayload()` 下发 `module_pages`） | 关掉模块的后台页不显示，常驻骨架页始终可见 |
| 运行守卫 | `FeatureGuardMiddleware` + `ModuleCatalog::routePrefixes()` | `feature_guard_mode=on` 时被关模块 API 返回 `4230`；`off` 只影响菜单，`log` 仅记录不拦截 |

### 5.3 后台操作边界

| 操作 | 结果 |
| --- | --- |
| 查看授权状态、激活授权码、停用授权 | `GET /admin/license`、`/admin/license/activate`、`/admin/license/deactivate` |
| 配置验签 | 仅可写 `license_verify_mode`、`license_remote_url`、`license_remote_pubkey`、`license_remote_ssl_verify`、`license_bind_domain`、`license_remote_timeout` |

未授权接口返回业务码 `402`，消息含 `module: <key>`。

## 6 内容审核

| 状态 | `status` | `audit_state` | 触发 |
| --- | --- | --- | --- |
| 正常发布 | 1 | 0 或 2 | 未命中审核 / 重审通过 |
| 管理员下架 | 0 | 0 | 后台「内容管理」隐藏 |
| 命中待审 | 0 | 1 | 敏感词 DFA、后台词库 `review`/`block`、AI 审核 |
| 重审通过 | 1 | 2 | 审核放行 |

编辑已发布动态会重新进入审核。命中待审时清除 `scheduled_at`，清 `timeline` / `popular` 命名空间版本，并向作者发站内信。

| 后台页面 | 处理对象 | 接口 |

| `posts.html` | 待审 / 下架（`status=0` 页签）、批量显示与隐藏 | `/admin/posts?status=`、`/admin/posts/status`、`/admin/posts/batch` |
| `reports.html` | 举报 | `/admin/reports`、`/admin/reports/resolve` |
| `appeals.html` | 申诉 | `/admin/appeals`、`/admin/appeal-handle` |

## 7 定时任务与运维

### 7.1 cron

| 频率 | 命令 |
| --- | --- |
| 每 5 分钟 | `curl -X POST -H 'X-Cron-Token: <cron_secret>' https://<域名>/api/cron/scheduled` |
| 每小时第 10 分钟 | `curl -X POST -H 'X-Cron-Token: <cron_secret>' https://<域名>/api/cron/badges` |
| 每分钟 | `curl -X POST -H 'X-Cron-Token: <cron_secret>' https://<域名>/api/cron/jobs` |
| 每天一次 | `curl -X POST -H 'X-Cron-Token: <cron_secret>' https://<域名>/api/cron/archive`（只增日志表滚动归档） |
| 每天一次 | `curl -X POST -H 'X-Cron-Token: <cron_secret>' https://<域名>/api/cron/circle-subscribes`（付费圈子订阅到期清退 + 提醒） |
| 每天一次 | `curl -X POST -H 'X-Cron-Token: <cron_secret>' https://<域名>/api/cron/vip-expire`（VIP 到期批量降级，清陈旧头像框缓存） |
| 每小时 | `php /path/to/woquan/bin/reconcile-counters.php` |
| 每天一次 | `php /path/to/woquan/bin/reconcile-wallet.php`（余额/积分流水对账，只读出报告，不自动改库） |

`cron_secret` 支持请求体 `secret` 或头 `X-Cron-Token`；留空时外部调度入口关闭。后台「系统设置」提供命令复制与「立即执行」。

`bin/reconcile-counters.php` 对账 4 列：`posts.comment_count`、`posts.like_count`、`circles.member_count`、`circles.post_count`。

`bin/reconcile-wallet.php` 只读核对 `users.balance` / `users.points` 与各自流水的累计，
漂移只出报告不自动改库（资金数据须人工核对）。VIP 降级二选一：有服务器 cron 用
`/api/cron/vip-expire`，无 HTTP cron 的站点用 `php bin/expire-vip.php`；读时兜底始终保留。

### 7.2 健康检查

```text
GET /health
{"code":200,"message":"success","data":{
  "status":"ok",
  "time":"2026-11-15T...",
  "checks":{
    "db":{"status":"ok","detail":"connected"},
    "cache":{"status":"ok","detail":"file"},
    "disk":{"status":"ok","detail":"63.2% free","free_mb":...,"total_mb":...},
    "migration":{"status":"ok","detail":"..."}
  }}}
```

`status` 取值：`ok` / `degraded` / `down`。

两条路径等价，由 Web 服务器转发方式决定用哪条：nginx `location = /health` 直转时用 `/health`；重写 / PATH_INFO 场景（`/api/index.php/health`）用 `/api/health`。

### 7.3 在线升级与回滚

| 步骤 | 接口 / 行为 |
| --- | --- |
| 版本检测 | `GET /admin/version-check` |
| 立即升级 | `POST /admin/upgrade`，上传 zip（上限 100MB），返回 `data.db_backup` / `data.code_backup` |
| 回滚恢复 | `POST /admin/rollback`，读取 `backups/index.json` 最近一次含 `upgrade=true` 的记录 |

升级执行顺序：备份数据库 → 备份代码 → 覆盖（保护 `config.php`、`.env`、`uploads/`、`cache/`、`logs/`、`backups/`）→ 同步版本 → 记录备份索引 → 执行数据库迁移 → 写文件指纹 → 清缓存。任一步失败自动回滚。备份文件为 `backups/hublog_db_{Ymd_His}.sql` 与 `backups/hublog_code_{Ymd_His}.zip`，仅保留最近 2 次。

| `admin/js/main.js` | `import nav-ui.js?v=`、`import('./icons.js?v=')` |
