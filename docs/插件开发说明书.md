# 我圈 插件开发说明书

> 本说明书对齐 2026-11-21 扩展闭环改造后的源码。新增能力（清单、生命周期、声明式迁移、后台注入、配置隔离、状态落库）均为**可选声明**：没有 `plugin.json` 的旧插件完全按 docblock 回退，行为与改造前一致。

## 1. 边界与能力范围

| 项 | 说明 |
| --- | --- |
| 开发目录 | `plugins/{插件名}/`；入口 `Plugin.php` 必填，其余文件按需（清单 `plugin.json`、设置页 `settings.html`） |
| 生效范围 | `api/index.php` 请求生命周期；外部 cron 调用 `/api/cron/*` 同样加载 |
| 前台加载 | `Plugin::loadAll()`：仅加载已启用的插件并调用 `init()`，业务钩子/路由在此注册 |
| 后台加载 | `Plugin::loadAdminScoped()`：仅在管理员鉴权通过后调用，只加载「已启用 + 有后台声明」者，**不调用 `init()`**；无声明插件在后台零 require、零执行 |
| 不加载插件 | 前台页面渲染（PHP 模板）、CLI 脚本；后台仅上述受控加载路径 |
| 可实现 | 监听业务事件、注册自定义 API 路由、响应发出后执行耗时任务、清单声明建表建列、注入后台菜单/设置页、插件独立配置读写 |
| 仍不可实现 | 前台模板渲染、定时任务注册、Queue 任务类型扩展、解绑监听（见 §10） |
| 启用状态 | `plugin_states.plugin_name` 为唯一可信源；`Cache('plugin_states')` 仅 300s 读缓存，可失效重建 |
| 清单文件 | `plugin.json` 优先；缺失时回退 `Plugin.php` 顶部 docblock（5 个内置插件即此模式） |
| 数据表 | 插件**不写裸 DDL**：在 `plugin.json` 用 `required_tables/required_columns` 声明，由核心生成 SQL |

新增能力全部是二开方可在自身插件目录内完成的事；只有新增核心表/路由/事件埋点才需要改核心源码。

## 2. 加载时序

### 2.1 前台 / API 请求（常规路径）

| 顺序 | 动作 |
| --- | --- |
| 1 | `Migration::run()`（不扫描 `plugins/`） |
| 2 | 惰性清理过期上传、定时发布调度 |
| 3 | `Plugin::loadAll()`：一次性迁移旧黑名单 → 解析清单 → `supportsCore()` 校验 → 按 `plugin_states` 过滤 → 加载并调用 `init()` |
| 4 | 构建 `Router`、加载 `routes.php` |
| 5 | 触发 `routes_register` |
| 6 | 路由分发、输出响应 |
| 7 | `Plugin::runDeferred()`：执行延迟任务 |

加载器只扫描 `plugins/` 的一级子目录；存在 `Plugin.php` 即视为插件；做 `realpath` 越界与目录名校验后包含文件、实例化、调用 `init()`。清单非法或 `core_version` 不满足的插件被跳过并记录日志，不影响其它插件与主流程。

### 2.2 后台请求（受控加载路径）

```
api/admin 请求 → AdminMiddleware + requireAdmin()
    → AdminPluginController::adminConfig()
    → Plugin::loadAdminScoped()：
        ① 查 isEnabled()，未启用跳过
        ② 查清单 admin_menu/admin_settings，两者皆空 → 连 Plugin.php 都不 require
        ③ 进入遍历前无条件定义 HUBLOG_ADMIN_SCOPE；然后对入选者 require_once + new Plugin()
        ④ 若实现 registerAdmin(PluginAdminContext $ctx) 则调用，绝不调 init()
        ⑤ 收集只读上下文的 menus()/settings() 下发给后台 SPA
```

加载时机严格在鉴权之后；`PluginAdminContext` 只暴露 `addMenu()/registerSettings()`，从类型上杜绝插件在后台渲染阶段改写核心状态（Q8）。详见 §16。

## 3. 包结构与约定

```
plugins/
├── .htaccess                       # 禁止 HTTP 直接访问 *.php、禁目录列表
└── {Name}/                          # 如 DemoExtension
    ├── plugin.json                  # 可选：清单（声明元信息/依赖/表/后台能力）
    ├── Plugin.php                   # 必填：唯一会被自动包含的入口
    └── settings.html                # 可选：后台设置页（声明 admin_settings 时读取）
```

| # | 约定 | 违反后果 |
| --- | --- | --- |
| 1 | 目录名 `plugins/{Name}/`，`Name` 匹配 `/^[a-zA-Z][a-zA-Z0-9]*$/`（不含 `-`、`_`、`.`） | 跳过加载并记录日志 |
| 2 | 必须有 `plugins/{Name}/Plugin.php` | 不被发现 |
| 3 | 命名空间 `Hublog\Plugin\{Name}`，类名 `Plugin` | 类不存在，插件无效 |
| 4 | 类可无参构造 | 实例化失败 |
| 5 | 提供 `public function init()`（可缺省） | 不提供则不注册任何业务监听 |
| 6 | `plugin.json` 的 `name` 必须与目录名完全一致 | 清单非法，插件被跳过 |
| 7 | `settings.html` 必须位于插件目录内、纯 HTML 无内联脚本 | realpath 越界校验拒绝 |

框架不要求基类或接口；`init/install/upgrade/uninstall/registerAdmin` 全部可选，`method_exists` 守卫。启停插件写 `plugin_states`，安装/升级/卸载由核心生命周期编排。

## 3.1 `plugin.json` 完整字段表

> 校验器为 PHP 手写等价规则（`is_*`/`preg_match`/`in_array`），不引入 json-schema 依赖；下表的 Schema 仅作契约描述与人工对照。`additionalProperties:false`——出现未定义字段即清单非法。

| 字段 | 类型 | 必填 | 缺省 / 回退 | 说明 |
| --- | --- | --- | --- | --- |
| `name` | string | ✅ | 目录名 | `^[A-Za-z][A-Za-z0-9]*$`，须与目录名一致 |
| `title` | string | 否 | docblock `@name` → 目录名 | 后台展示名，≤128 |
| `description` | string | 否 | docblock `@description` → `''` | ≤1024 |
| `version` | string | 否 | docblock `@version` → `1.0.0` | `^\d+\.\d+\.\d+`，`upgrade($from,$to)` 的版本源 |
| `author` / `link` | string | 否 | docblock 同名 tag → `''` | 后台展示 |
| `core_version` | string | 否 | `*` | 依赖核心版本表达式，见 §3.3 |
| `permissions` | string[] | 否 | `[]` | 所需权限点；**仅提示，不自动授权**，缺失时给可读错误 |
| `hooks` | string[] | 否 | `[]` | 监听的事件名（信息性，便于后台审计） |
| `required_tables` | object[] | 否 | `[]` | 声明式建表 spec，见 §3.4 |
| `required_columns` | object[] | 否 | `[]` | 给已有表追加列，见 §3.4 |
| `drop_tables_on_uninstall` | bool | 否 | `false` | true 才允许卸载删表，且需二次确认令牌 |
| `admin_menu` | object[] | 否 | `[]` | 后台菜单声明，见 §16 |
| `admin_settings` | object | 否 | `null` | 后台设置页声明，见 §16 |
| `install_hook` / `upgrade_hook` / `uninstall_hook` | bool | 否 | `false` | 钩子存在声明位（当前仅校验与存储，无生产读取点；实际调用一律以 `method_exists` 为准） |

## 3.2 元信息：清单优先、docblock 回退

`PluginManifest::fromDir()` 先读 `plugin.json`；文件不存在时完全退化为 `Plugin::readMeta()` 的 docblock 输出（见 §4.1）。清单里未填的 `title/description/version/author/link` 也会从 docblock 补齐，因此旧插件无需迁移。

## 3.3 `core_version` 语法

自实现 `version_compare` 子集，零依赖。空格或逗号分隔，全部条件 AND：

| 形式 | 含义 |
| --- | --- |
| `>=X.Y.Z` / `>X.Y.Z` / `<=X.Y.Z` / `<X.Y.Z` / `=X.Y.Z` | 版本比较（`=` 等同 `==`） |
| `X.Y.Z` | 等价于 `>=X.Y.Z` |
| `*` | 不校验 |

示例：`">=2.16.0 <3.0.0"`。非法表达式在清单校验阶段即报错并拒绝激活；不满足时 `Logger::error` 给出可读原因，后台可见。注意：不支持 Composer 的 `^`/`~`/`||` 复杂表达式。

## 3.4 声明式迁移边界（`required_tables` / `required_columns`）

| 项 | 规则 |
| --- | --- |
| 类型白名单 | `int / bigint / tinyint / varchar / text / longtext / datetime / decimal`；其它类型清单非法 |
| varchar | 必须声明整数 `length`（1~4000），否则清单非法 |
| 表前缀 | `required_tables[].name` 必须匹配 `/^plugin_[a-zA-Z][a-zA-Z0-9_]{0,55}$/`（`plugin_` 前缀 + 首字母 + 至多 55 位字母数字下划线），禁止在核心/他人表上建表 |
| 裸 SQL | 禁止任何 `ddl`/`sql`/`raw` 字段（`additionalProperties:false`）；声明值中出现 `DROP/TRUNCATE/RENAME` 关键字双保险拦截 |
| 契约冲突 | 与 `MigrationContract::REQUIRED_TABLES/REQUIRED_COLUMN_NAMES` 同名但结构不一致 → 拒绝安装 |
| 跨插件冲突 | 同名 `plugin_*` 表由 `plugin_configs._schema_tables` 登记归属，后安装者被拒绝 |
| 幂等 | 表存在跳过、缺列逐列 `ALTER`；安装/升级可重复执行 |
| 追加列 | `required_columns` 给已有表加列，**卸载时永不删除**（避免破坏核心表） |
| 卸载 | 默认仅 `enabled=0` 保留数据；只有 `drop_tables_on_uninstall:true` + 已授权 `confirm_token` 才删声明内的 `plugin_*` 表 |

DDL 由 `PluginSchemaMigrator` 统一生成、插件侧不拼任何 SQL 串。失败写 `plugin_states.last_error` + `Logger::error`，状态置 `failed`。

## 4. 最小插件

```php
<?php
/**
 * @name 示例插件
 * @description 发帖后做一件小事
 * @version 1.0.0
 * @author Me
 * @link https://example.com
 */
namespace Hublog\Plugin\Demo;

use Hublog\Core\Hook;
use Hublog\Core\Plugin as PluginManager;
use Hublog\Core\Logger;

class Plugin
{
    public function init(): void
    {
        Hook::addAction('post_created', [self::class, 'onPostCreated'], 10);
    }

    public static function onPostCreated(int $postId, int $userId): void
    {
        PluginManager::defer(function () use ($postId, $userId) {
            try {
                Logger::info("[Demo] 新动态 {$postId} by {$userId}");
            } catch (\Throwable $e) {
                Logger::error('[Demo] 延迟任务失败: ' . $e->getMessage());
            }
        });
    }
}
```

放入 `plugins/Demo/Plugin.php` 即被后台发现，默认启用（黑名单初始为空）。

### 4.1 docblock 元信息

后台列表读取 `Plugin.php` 前 4096 字节的 docblock：

| tag | 后台字段 | 缺省值 |
| --- | --- | --- |
| `@name` | `title` | 目录名 |
| `@description` | `description` | 空串（支持多行续行） |
| `@version` | `version` | `1.0.0` |
| `@author` | `author` | 空串 |
| `@link` | `link` | 空串 |

列表返回 `name / title / description / version / author / link / enabled / path`，按名称排序；带清单的插件额外追加 `core_version / install_status / installed_version / admin_menu`（原 8 字段的键名、顺序、取值口径不变）。

完整可运行示例见 `plugins/DemoExtension/`（清单 + 建表 + 设置页 + 钩子全链路），本说明书 §18 逐链路解读。

## 5. Hook API

函数名为驼峰式，无下划线别名。

| 函数 | 语义 |
| --- | --- |
| `Hook::addAction(string $tag, callable $cb, int $priority = 10)` | 注册事件监听 |
| `Hook::doAction(string $tag, ...$args)` | 触发事件，回调返回值丢弃 |
| `Hook::addFilter(string $tag, callable $cb, int $priority = 10)` | 注册过滤器 |
| `Hook::applyFilter(string $tag, mixed $value, ...$args)` | 链式传值并返回最终结果；无监听则原样返回 |
| `Hook::hasAction(string $tag)` / `Hook::hasFilter(string $tag)` | 判断是否存在监听 |

- `priority` 默认 `10`，数值越小越先执行；同优先级按注册先后。
- `applyFilter` 把上一个回调的返回值作为下一个的 `$value`。
- 当前实际生效的是 Action，Filter 尚无调用点。
- 无解绑 API，停用插件在下一次 API 请求生效。

### 5.1 可用事件

| 事件 | 触发时机 | 参数 | 内置监听者 |
| --- | --- | --- | --- |
| `routes_register` | 静态路由表加载后、分发前 | `$router` | SmartSearch、SmartRecommend |
| `post_created` | 发帖成功（含转发 / 投票类发帖） | `$postId, $userId` | ContentAudit(5)、SmartSummary(15)、SmartSearch(15)、AiComment(20) |
| `post_updated` | 编辑内容后 | `$id, $userId` | ContentAudit(5) |
| `post_deleted` | 删除动态后 | `$id, $userId` | 无 |
| `post_viewed` | 详情浏览计数 | `$id, $currentUserId ?? 0` | SmartRecommend |
| `post_liked` | 点赞 / 取消点赞 | `$postId, $userId, $liked(bool)` | SmartRecommend |
| `post_commented` | 评论写入后 | `$postId, $userId, $commentId` | ContentAudit(5)、SmartRecommend |

转发 / 投票类发帖触发 `post_created` 而非 `post_updated`。当前无用户注册、评论创建 / 删除、回复、私信、支付、登录事件；新增事件需在核心控制器埋点。

**回调签名须与上表参数严格对齐**：`doAction` 用 `...$args` 按位置展开调用，参数个数或顺序不一致不会报错，但语义会出错。

## 6. 自定义 API 路由

```php
use Hublog\Core\Router;
use Hublog\Core\Request;
use Hublog\Core\Response;

public function init(): void {
    Hook::addAction('routes_register', [self::class, 'registerRoutes']);
}

public static function registerRoutes(Router $router): void {
    // 写全路径；插件路由继承四条基线中间件，不重复声明（详见本节约束）
    $router->get('/api/demo/ping', [self::class, 'ping']);
}

public static function ping(Request $request): Response {
    return Response::success(['pong' => true]);
}
```

`Router` 支持 `get / post / put / delete / patch($path, $handler, $middleware)`。内置范例：`/api/posts/recommend`、`/api/search/semantic`。

约束：

- 插件路由在一个空前缀分组内注册，**继承四条基线中间件**（`RateLimitMiddleware`、`CsrfMiddleware`、`LicenseMiddleware`、`FeatureGuardMiddleware`），无需也不应重复声明；该分组**不含** Auth / Admin 鉴权，需管理员身份的路由请在回调内自行校验。
- 路由注册为同路径覆盖赋值，后注册者可覆盖已有路由。上线前核对路径不与核心路由冲突。

## 7. 异步任务

```php
\Hublog\Core\Plugin::defer(function () use ($postId) {
    // 外部 API、压缩、批量写库等耗时操作
});
```

`defer()` 把回调排入队列；框架在响应完整输出后断开客户端连接再逐个执行，异常统一记日志，不影响已发出的响应。

**钩子回调内不得直接调用 `fastcgi_finish_request()`**；此时响应体尚未输出，提前 flush 会导致接口返回空内容。`JobQueue` 当前识别两种任务类型——视频压缩（`compress_video`）与插件异步任务（`plugin_task`，核心 `api/index.php` 已用后者入队）；类型由核心常量固定，插件无法注册新类型。

## 8. 插件配置 API（`plugin_configs`，与核心 settings 隔离）

插件配置落在独立表 `plugin_configs(plugin_name, config_key, config_value)`，唯一键 `uk_plugin_config(plugin_name, config_key)` 保证幂等 upsert；**不进核心 `settings` 白名单**。所有读写路由属 `/api/admin` 组，由 `AdminMiddleware + requireAdmin()` 双重鉴权。

| 用途 | 接口 | 参数 / 返回 |
| --- | --- | --- |
| 读 | `GET /api/admin/plugin-config` | `plugin_name` + `key` 必填 → `{value}`（未配置为 `''`） |
| 写 | `POST /api/admin/plugin-config` | `plugin_name` + `key` + `value` → `{ok:true}`（同键覆盖） |
| 设置页 HTML | `GET /api/admin/plugin-settings-page` | `plugin_name` 必填 → `text/html`；realpath 越界 + 后缀白名单校验 |

**配置键约定**：`config_key` 用 snake_case，作用域按插件名隔离。`_schema_tables` 是核心保留键（T02 登记插件建表归属，防跨插件同名表冲突），`PluginConfigRepository::get()/set()/delete()` 对它的读取 / 写入 / 删除一律抛 403 HublogException，`all()` 也不回显——插件不可伪造归属绕过拦截。

设置页 HTML 里的控件加 `data-config-key="your_key"` 属性，`admin/js/plugin-settings.js` 会自动回填已有值、点击保存时逐键 upsert；页面本身保持纯 HTML，**不得含内联 script**（核心统一注入行为）。

旧的核心 `settings` 读取方式（如 `ai_comment_enabled`）仍可用，但那是历史内置插件的行为；新插件请走本节 API。

## 9. 启用与停用（状态落库）

| 环节 | 说明 |
| --- | --- |
| 列表 | `GET /api/admin/plugins` → `Plugin::scanAll()`，入参出参保持不变 |
| 启停 | `PUT /api/admin/plugins`，请求体 `{"name":"Demo","enabled":false}` → `Response::success(['enabled'=>false], msg)`，**入参出参逐字不变** |
| 权限 | 属 `/api/admin` 路由组，需管理员身份与 CSRF；不挂授权模块 |
| 可信源 | `plugin_states.plugin_name` 主键；`enabled` ∈ {0,1}，`install_status` ∈ {installed/failed/not_installed} |
| 缓存 | `Cache('plugin_states')` TTL 300 只读缓存；任何写操作后 `Cache::delete`，清缓存后从 DB 重建，状态不丢 |
| 升级兼容 | 旧 `disabled_plugins` 黑名单由 `PluginStateRepository::migrateLegacyBlacklist()` 一次性幂等入库；无缓存数据时新插件默认启用 |

`enabled` 与 `install_status` 是两个独立维度：停用不等于卸载，卸载默认也不删数据。停用对当前请求不生效（下一次请求加载时才过滤）。

安装 / 升级 / 卸载的生命周期接口见 §15；后台菜单/设置页注入见 §16。

## 11. 自动加载与多文件

自动加载器只注册 `Hublog\Core\`、`Hublog\Controllers\`、`Hublog\Middleware\` 三个前缀，`composer.json` 无 `autoload` 段。插件类由加载器对 `Plugin.php` 手动包含。

**只有 `Plugin.php` 会被自动包含。** 拆到 `Helper.php` 或子目录的类须在 `Plugin.php` 内自行 `require_once`，或由后端扩展自动加载映射。内置插件均为单文件。

Web 服务器：`plugins/.htaccess`、`nginx.conf`、`web.config`、`Caddyfile` 均已禁止直接访问插件 PHP 文件（`Caddyfile` 用 `@pluginsPhp path_regexp` 规则返回 404）。

## 14. 插件生命周期 vs AppCenterInstaller 应用包部署（E1-4 辨析）

两套机制名字都带「安装」，但**对象、入口、副作用完全不同，互不调用、互不覆盖**：

| 维度 | 插件生命周期（plugin lifecycle） | AppCenterInstaller（应用包部署） |
| --- | --- | --- |
| 操作对象 | `plugins/{Name}` 目录内的一个插件 | 应用中心下发的 zip 应用包文件 |
| 入口 | `PluginLifecycle::install/upgrade/uninstall` | `AppCenterInstaller` 自身的下载、校验、解压、版本切换流程 |
| 元数据 | `plugin.json` 清单（缺失时回退 Plugin.php docblock） | 应用包清单 / 版本记录 |
| 钩子 | `install()` / `upgrade($from,$to)` / `uninstall()`，全部可选，`method_exists` 守卫 | 无插件钩子概念 |
| 结构变更 | `required_tables` / `required_columns` 由核心生成 DDL，禁止插件裸 SQL | 应用包文件替换，不生成插件表 |
| 状态落库 | `plugin_states`（启停 + 安装状态 + 失败原因） | 应用中心自己的版本 / 安装记录 |
| 卸载语义 | 默认 `enabled=0` 保留数据；仅 `drop_tables_on_uninstall:true` + 已授权确认才删声明内 `plugin_*` 表 | 应用包文件回滚 / 删除，不等于插件卸载 |

约束：

- 插件钩子统一称 **plugin lifecycle**，不要简写成「应用安装」；
- `AppCenterInstaller` 不得调用 `PluginLifecycle`，反之亦然；应用中心安装/卸载应用包时**不会**触发插件的 `install()/upgrade()/uninstall()`；
- 本文所述插件安装状态只来自 `plugin_states`，与应用中心版本状态是两个独立维度；
- 应用包部署（`AppCenterInstaller`）只做文件替换，不会建表；其中的插件部署后默认未安装、未建表，须经 `POST /api/admin/plugins/install`（`AdminPluginController` → `PluginLifecycle::installFrom()` → `PluginSchemaMigrator::apply()`）才建表，`Plugin::loadAll()` 只加载并 `init()` 不建表；是否启用另由 `plugin_states` 决定；应用包文件回滚不等于插件数据回滚；
- 排障时先看 `plugin_states.install_status/last_error`（插件维度），再看应用中心版本记录（文件维度），不要混为一谈。

## 15. 生命周期钩子（install / upgrade / uninstall）

### 15.1 签名与守卫

| 方法 | 固定签名 | 调用时机 | 实现方式 |
| --- | --- | --- | --- |
| `install()` | `public function install(): void` | 安装插件、表结构应用后 | 可选，`method_exists` 守卫 |
| `upgrade()` | `public function upgrade(string $fromVersion, string $toVersion): void` | 升级插件、表结构补齐后 | 可选，`method_exists` 守卫 |
| `uninstall()` | `public function uninstall(): void` | 卸载插件，在删表后、停用前调用（此时声明的 `plugin_*` 表已删除） | 可选，`method_exists` 守卫 |
| `registerAdmin()` | `public function registerAdmin(PluginAdminContext $ctx): void` | 后台受控加载，**不调 `init()`** | 可选，`method_exists` 守卫 |

全部可选：未实现时核心静默跳过，5 个内置插件不实现任何生命周期钩子，行为零变化。钩子抛出的异常由 `PluginLifecycle` 捕获，写 `plugin_states.last_error` + `Logger::error()`，状态置 `failed`，不中断请求；后台列表可见失败原因。

**边界**：`install()/upgrade()` 只做数据初始化与日志，**不得拼裸 DDL**——建表建列一律走 §3.4 的清单声明。删表也不是 `uninstall()` 的职责，由核心按清单 + 授权令牌执行。

### 15.2 接口与错误码

| 接口 | 关键入参 | 成功返回 | 失败 |
| --- | --- | --- | --- |
| `POST /api/admin/plugins/install` | `name`, `confirm` | `{name, install_status, installed_version}` | 400 插件名非法（`validatedName` 失败）；生命周期失败按 reason 文本归类：含「核心版本」或「清单」→ 422，其余（含版本依赖不满足、清单字段非法等文案）→ 500，无单独 403（仅删表令牌无效时为 403，见 uninstall） |
| `POST /api/admin/plugins/upgrade` | `name`, `from`, `to` | `{name, from, to, install_status}` | 同上 |
| `POST /api/admin/plugins/uninstall` | `name`；删表时另需 `confirm_token` | `{name, enabled:false, data_kept, install_status, dropped}` | 缺令牌 / 令牌无效 → 403 |

**删表二次确认令牌**：`hash_hmac('sha256', 'plugin:<name>:drop', settings.cron_secret)`，由 `AdminPluginController::adminConfig()` 下发给已鉴权管理员。安全口径：

- 未声明 `drop_tables_on_uninstall` → 不校验令牌，数据原样保留（`data_kept:true`）；
- 声明删表但令牌缺失/不匹配 → 403；
- **cron_secret 未配置时 fail-closed**：不下发令牌、且拒绝任何令牌（含离线计算的 `hash_hmac(...,'')`），删表不可进行——与 `AdminToolsController` 对 `backup_cron_secret` 空值的拒绝口径一致；
- 令牌比对用 `hash_equals` 防时序攻击。

安装幂等：重复执行不报错、不产生多余 DDL；`required_columns` 追加的列在卸载时永不删除。

## 16. 后台菜单与设置页注入（Q8 受控加载）

插件可通过清单声明 + 可选 `registerAdmin()` 向后台注入入口，权限收口在核心。

### 16.1 清单声明

```json
{
  "admin_menu": [
    { "group": "content", "title": "演示笔记", "page": "plugin-demo-notes", "icon": "note", "sort": 100 }
  ],
  "admin_settings": {
    "page": "settings.html", "config_scope": "demo", "title": "演示扩展设置"
  }
}
```

- `group` 取 `overview/content/user/safety/commerce/system`，对应既有 `nav-*` 展示分组；
- `page` 必须 `^plugin-[a-zA-Z][a-zA-Z0-9-]{0,47}$`；菜单点击最终落到 `/api/admin/...` 路由，由核心统一鉴权，插件不自持鉴权逻辑；
- `admin_settings.page` 固定 `settings.html`；`config_scope` 为 `^[a-zA-Z][a-zA-Z0-9_]{0,47}$`；每个插件最多一份设置页，后声明覆盖前声明。

### 16.2 代码侧注册（可选）

```php
use Hublog\Core\PluginAdminContext;

public function registerAdmin(PluginAdminContext $ctx): void
{
    $ctx->addMenu(['group' => 'content', 'title' => '演示笔记', 'page' => 'plugin-demo-notes']);
    $ctx->registerSettings(['page' => 'settings.html', 'config_scope' => 'demo', 'title' => '演示扩展设置']);
}
```

清单声明已由核心注入上下文；`registerAdmin()` 用于按需追加（同 page / 同插件由上下文去重，清单优先）。上下文只暴露 `addMenu()/registerSettings()` 与只读 `menus()/settings()`，无 Database/Cache/Router setter。后台作用域会定义 `HUBLOG_ADMIN_SCOPE` 常量供插件自检，**绝不调用 `init()`**，业务钩子/路由在后台完全不注册。

### 16.3 查看与启停效果

- `GET /api/admin/plugin-admin-config` → `{menus:[...], settings:[...]}`，仅已启用且有后台声明的插件被加载；
- 启用插件 → 菜单出现；禁用 → 消失；
- 设置页 HTML 从插件目录读取（`realpath` 越界 + 后缀白名单校验），配置项读写走 §8 的 `plugin-config` API；
- 核心 `settings` 白名单不新增任何插件键。

## 17. G5 文档工具链用法

路由与 OpenAPI 一致性由零依赖脚本保证（不复活 Python 链、无新增 composer 依赖）：

```bash
php scripts/parse_routes.php --pretty        # 解析 routes.php，输出 {method,path,middlewares} JSON
php scripts/check_route_docs.php             # 对账，退出 0=通过 / 1=门禁失败 / 2=环境问题
php scripts/check_route_docs.php --json      # 机器可读差异报告
composer docs:routes                         # 上述解析的便捷入口
composer docs:check                          # 上述对账的便捷入口
```

规则：

1. `missing - allowed_missing` 非空 → 退出 1（新增路由未入文档）；
2. 当前缺失数 > `docs/openapi_route_baseline.json` 的 `baseline_count` → 退出 1（差异只减不增）；
3. 差异报告定位到具体 `METHOD /path`，区分「路径不存在」与「方法未文档化」。

新增路由必须**同时**：进 `openapi.yaml`、进 `api/tests/LicenseRouteCoverageTest::ROUTE_CLASS_MAP`、过 G5 对账门禁。存量补齐后可 `php scripts/check_route_docs.php --write-baseline` 重新固化（人工评审后入库），基线数下降是合规的。文档即基座资产，维护者按本节可独立跑通对账。

## 18. DemoExtension 全链路示例解读

`plugins/DemoExtension/` 是本仓库唯一新增的示例插件目录，演示机制、不含垂直业务（C1）。按下列链路即可从零验证：

| 步骤 | 动作 | 证据 |
| --- | --- | --- |
| 1 扫描 | `Plugin::scanAll()` | 识别 `DemoExtension`，带 `core_version/install_status/admin_menu` |
| 2 安装 | `POST /api/admin/plugins/install {name:"DemoExtension", confirm:true}` | 清单声明的 `plugin_demo_notes` 建成；`install()` 初始化 `post_hook_enabled=1` |
| 3 配置 | 后台「演示扩展设置」页改开关并保存 | 写入 `plugin_configs`，核心 `settings` 无新增键 |
