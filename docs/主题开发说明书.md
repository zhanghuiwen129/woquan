# 我圈 主题开发说明书

## 1. 核心原则

**主题开发的全部工作都在 `templates/{主题id}/` 内完成，不需要改动任何框架源码。**

框架层（`index.php`、`api/`、`admin/`、`scripts/`）已经做成主题无关：新增一套主题 = 放好目录 + 后台切换，零 PHP 改动、零后端发布。下表是这条原则的具体边界：

| 要做什么 | 改哪里 | 动框架源码 |
| --- | --- | --- |
| 新建主题、改页面结构 / 样式 / 交互 | 主题目录内的 HTML、CSS、JS | 否 |
| 增加页面 URL | 主题目录放同名 `.html`，自动获得路由 | 否 |
| 服务端渲染首屏（爬虫可读、消除占位符闪屏） | 主题目录放 `ssr.php` + `partials/` | 否 |
| 增加后台外观选项 | 主题目录放 `settings.json`，字段自描述样式映射 | 否 |
| 生成 / 更新 DOM 契约 | 运行审计脚本，结果写进主题目录的 `contract.json` | 否 |
| 启用 / 切换主题 | 后台「扩展管理 → 外观主题」 | 否 |
| 新增业务接口 / 数据表 / 后台菜单 | 后端开发流程（不属于主题开发） | 是 |

影响范围：前台网页与 H5。App 客户端（uni-app 原生页面）、后台管理界面、后端接口与数据库均不受主题影响。

**与插件的边界**：主题负责前台展示（HTML/CSS/JS/SSR），**不含插件生命周期**（`install/upgrade/uninstall` 与 `plugin.json` 清单均属 `plugins/` 目录）；后台菜单与设置页注入也**仅插件**可做，主题只能通过 `settings.json` 提供后台外观选项。单页内容由后端 `pages` 表与 `GET /api/pages/{slug}` 提供，主题不承担建表与发布逻辑。详见 `docs/插件开发说明书.md` §1、§15、§16。

## 2. 主题包结构

```
templates/{id}/                       # id 匹配 /^[a-zA-Z0-9_-]+$/
├── theme.json                       # 必需：主题清单
├── contract.json                    # 必需：DOM 契约（审计脚本生成）
├── preview.svg                      # 建议：后台卡片预览图
├── settings.json                    # 可选：外观设置表单 + 样式自描述
├── index.html … points.html         # 必需：18 个骨架页
├── {自定义页}.html                  # 可选：扩展页，自动获得 /{name} 路由
├── ssr.php                          # 可选：首屏服务端渲染器（返回 callable）
├── partials/                        # 可选：服务端展开的公共片段
│   ├── topbar.html
│   ├── tabbar.html
│   └── page-tail.html
└── assets/
    ├── css/style.css                # 必需
    ├── js/app.js                    # 必需：ES Module 入口，每个 HTML 都要引入
    ├── js/modules/                  # 必需
    ├── images/default-avatar.svg    # 必需
    └── vendor/                      # 按需：marked / DOMPurify / vditor 整目录
```

以 `templates/zixunfeed/` 为完整范例：18 个骨架页 + 4 个扩展页（`login/video/ranking/write`）、3 个 `partials/`、`ssr.php`、`settings.json`、`contract.json` 和完整 `assets/`，全部自包含。

### 2.1 校验与启用

框架有两级校验，含义不同：

| 校验 | 检查内容 | 不通过的后果 |
| --- | --- | --- |
| 启用准入（`Theme::resolve()`） | 名称格式合法、目录存在、有 `index.html` 和 `contract.json`、`realpath` 未越出 `templates/` | 静默回退默认主题 |
| 完整性标记（`Theme::discover()`） | 清单必填字段、18 个骨架页、必需资源、契约清单 | 后台卡片标 `invalid` 并列出 `issues`，不参与启用 |

`theme.json` 必填字段为 `name`、`version`、`contract`。18 个骨架页：`index, post, user, followers, following, pinned, favorites, go, category, topic, circles, circle, search, chat, messages, reset-password, wallet, points`。

主题名只允许 `[A-Za-z0-9_-]`、长度 ≤ 64；路径经 `realpath` 校验必须位于 `templates/` 内。

> `contract.json` 是启用的硬门槛：没跑过契约审计的主题不会被启用，避免半成品主题静默丢功能。

### 2.2 资源路径

前台注入 `<base href="/templates/{id}/">`，CSS、JS 以及 JS 内拼接的图片路径全部以此为基准。因此**每个主题必须自带完整的 `assets/` 副本**，不得只放差异文件去引用其它主题目录。`<base>` 一个标签同时决定 CSS、JS 与 JS 内图片三者的解析。

## 3. 路由

| URL | 模板 | URL | 模板 |
| --- | --- | --- | --- |
| `/`（及其它未匹配） | `index.html` | `/p/{id}` | `post.html` |
| `/u/{name}` | `user.html` | `/c/{id}` | `category.html` |
| `/u/{name}/followers`、`/followers` | `followers.html` | `/topic/{name}` | `topic.html` |
| `/u/{name}/following`、`/following` | `following.html` | `/circles` | `circles.html` |
| `/pinned` | `pinned.html` | `/circle/{id}` | `circle.html` |
| `/favorites` | `favorites.html` | `/search` | `search.html` |
| `/go` | `go.html` | `/chat` | `chat.html` |
| `/reset-password` | `reset-password.html` | `/messages` | `messages.html` |
| `/wallet` | `wallet.html` | `/points` | `points.html` |

`/p/{id}`、`/c/{id}`、`/topic/{name}`、`/search`、`/u/{name}` 会预取详情、关键词或用户名，用于 SEO 标签与首屏数据。

### 3.1 扩展页

主题目录放 `xxx.html` 即可通过 `/xxx` 访问。规则：

- URL 段为单段 `[a-z0-9_-]+`；
- `index / install / health / api / admin / cron` 为保留字；
- 文件须存在于当前启用主题目录内，否则回退首页；
- 每个扩展页都要引入 `assets/js/app.js`。

### 3.2 伪静态与页面前缀

| `settings.url_rewrite` | URL 形式 | `HUBLOG_PAGE_BASE` |
| --- | --- | --- |
| `1` | `/search`、`/u/admin`（需 Web 服务器重写规则） | 根目录为空，子目录为 `/sub` |
| `0` | `/index.php/search`（PATH_INFO，开箱即用） | 根目录为 `/index.php` |

页面内跳转一律用 `window.HUBLOG_PAGE_BASE` 拼前缀，模板里可用 `{{PAGE_BASE}}/link` 写站内绝对路径，两种部署形式都正确。

## 4. 两类主题与开发起点

| | 复用基准 JS | 独立前端栈 |
| --- | --- | --- |
| 范例 | `templates/moments/` | `templates/zixunfeed/` |
| `theme.json.inherits_js` | `moments` | 自身主题 id |
| 做法 | 整目录复制 `moments/`，改 CSS 变量覆盖层与少量 HTML | 自写 HTML 骨架与 `assets/js/` 全部模块 |
| 契约门禁 | 守住 `moments/contract.json` 的关键 id / class | 校验 18 骨架页、必需资源、每页引入 `app.js` |
| 功能 | 继承基准主题全部交互 | 自行逐页对接接口；可启用 SSR / partials / 外观自描述 |

`inherits_js` 取值须与实际 JS 来源一致：运行时 JS 一律按 `<base href>` 从当前主题自己的 `assets/js/` 加载，声明与来源不符只会导致契约审计判断错误。

## 5. `theme.json`

```json
{
  "id": "mytheme",
  "name": "我的主题",
  "version": "1.0.0",
  "author": "Me",
  "description": "一句话描述",
  "preview": "preview.svg",
  "contract": "1.0",
  "inherits_js": "moments",
  "content_format": "markdown",
  "inline_media": false,
  "skin": {
    "variables": ["--brand", "--bg", "--card"],
    "dark_mode": true,
    "custom_color": true
  }
}
```

| 字段 | 必需 | 作用 |
| --- | --- | --- |
| `name` / `version` / `contract` | 是 | 缺一即 invalid |
| `id` | 否 | 显示用；目录名为真正 id |
| `preview` | 否 | 相对路径；文件不存在判为 invalid |
| `inherits_js` | 否（默认 `moments`） | 决定契约审计走哪条规则，见第 4 节 |
| `content_format` | 否（启用准入不校验，审计脚本要求，见 10.1） | `markdown` / `html`，写页提交 `posts.content` 的格式；审计脚本校验，见 10.1 |
| `inline_media` | 否（默认 `false`） | 是否支持正文任意位置插入媒体；置 `true` 触发内容契约强校验，见 10.1 |
| `skin` | 否 | 皮肤变量、暗黑模式、自定义主色声明；仅为声明性元数据，框架当前不读取（暗黑模式：有 `settings.json` 的主题如 `zixunfeed` 走其中 `dark_mode` 选项，无该文件的主题如基准 `moments` 走前端 localStorage；自定义主色一律由前端 localStorage 实现） |

后台通过主题发现接口获得全部主题及 `valid` / `issues` / `active`（后台 SPA 经 `/api/index.php/...` 前缀调用）。后台卡片选中态以该接口的 `active` 为准。

## 6. `contract.json` 与审计

```bash
node scripts/audit-theme.js --gen                     # 重新生成基准主题 moments 的 contract.json
node scripts/audit-theme.js --gen --theme=mytheme     # 生成指定主题自己的契约
node scripts/audit-theme.js                           # 审计全部含 theme.json 的主题
node scripts/audit-theme.js mytheme                   # 审计指定主题
```

生成逻辑：扫描主题 HTML 得到 id / class 基线，扫描 JS 中 `getElementById('x')` 与 `querySelector('#x'/'.x')` 的字面量引用，取交集得到关键契约；运行时动态生成的 id 不计入。

| 主题类型 | 审计规则 |
| --- | --- |
| `inherits_js = moments` | 关键 id / class 缺一即失败；完整基线缺项仅告警 |
| 独立主题 | 校验 18 骨架页、必需资源、每页引入 `app.js` |
| 全部主题 | 内容契约：`content_format` / `inline_media` 声明与占位符语法，见 10.1 |

每次改完主题 HTML 都要重新生成契约并跑审计。内容契约随同一次 `node scripts/audit-theme.js` 输出，不单独写进 `contract.json`。审计脚本按 `*.html` 收集页面；文件名含「预览 / preview」的设计稿只在独立主题的「是否引入 `app.js`」检查中被忽略（仍参与 DOM 提取与内容契约扫描）；`partials/` 下的片段同样不参与 `app.js` 引入检查。

## 7. 首屏服务端渲染（SSR）

框架按约定自动启用首屏服务端渲染，**主题只需在自己目录内按约定放文件，框架层零改动**。满足任一条件即进入该管线：主题有 `ssr.php`、有 `partials/` 目录、或 HTML 含 `{{SSR_` / `{{POST_`。整段流程异常安全：任一步失败降级为空首屏，不会 500，也不会把花括号吐到页面上。

### 7.1 公共片段 `partials/`

在页面里写注释形式的引入标记，框架在服务端展开：

```html
<!-- @include partials/topbar.html -->
```

- 片段放在 `partials/[A-Za-z0-9_-]+\.html`，路径固定在当前主题目录内，`realpath` 校验防穿越。
- 服务端展开后，前端 `includes.js` 找不到 `@include` 注释便直接跳过，不会重复插入。
- 片段读取失败时保留原注释，交给前端 fetch 内联兜底。

**频道锚点必须写成注释形式** `<!--{{SSR_CHANNELS}}-->`：框架会先整体替换这个锚点，避免注入的 `<a>` 被 HTML 注释吞掉；裸写 `{{SSR_CHANNELS}}` 在 fetch 降级路径会闪现花括号。`partials/topbar.html` 用的就是注释形式。

### 7.2 列表渲染器 `ssr.php`

文件放在主题根目录，`require` 后必须返回一个 callable。框架调用它时传入一个关联数组：

| 键 | 含义 |
| --- | --- |
| `path` | 去掉部署前缀后的请求路径，如 `/`、`/c/3`、`/topic/xxx` |
| `query` | `$_GET` 数组 |
| `pageBase` | 页面 URL 前缀 |
| `origin` / `baseUrl` | 站点来源 / 带部署路径的站点根地址 |
| `themeOpts` | 当前主题的外观选项（已合并默认值） |

渲染器返回关联数组，键名 `foo` 自动映射占位符 `{{SSR_FOO}}`（键名须匹配 `/^[a-z][a-z0-9_]*$/`，值须为字符串，非字符串按空串处理）。框架约定的常用键：

| 返回键 | 占位符 | 用途 |
| --- | --- | --- |
| `feed` | `{{SSR_FEED}}` | 主列表容器 HTML（含真实 `<a href>`，供爬虫抓取） |
| `hero` / `flash` | `{{SSR_HERO}}` / `{{SSR_FLASH}}` | 首页轮播 / 快讯条 |
| `side` / `chips` | `{{SSR_SIDE}}` / `{{SSR_CHIPS}}` | 侧栏 / 话题 chips |
| `channels` / `cathead` / `hotwords` | `{{SSR_CHANNELS}}` / `{{SSR_CATHEAD}}` / `{{SSR_HOTWORDS}}` | 频道栏 / 分类头 / 热词 |
| `items` | — | `[{id,title,url}]`，框架据此生成 ItemList JSON-LD 结构化数据 |
| `meta` | `{{SSR_META}}` | 页面 meta 标签 |

新增片段无需在框架登记：渲染器多返回一个合法键，模板里写对应占位符即可。`zixunfeed/ssr.php` 服务端渲染首页 / 分类 / 话题 / 用户 / 搜索 / 热榜 / 视频七个列表页，只输出公开动态，JS 接管后用同一批数据原地替换。

### 7.3 详情页 `{{POST_*}}`

详情页首屏由框架通用渲染，主题在 `post.html` 放对应占位符即可：

| 占位符 | 内容 |
| --- | --- |
| `{{POST_TITLE}}` | 标题（无标题时取正文前 40 字） |
| `{{POST_AUTHOR}}` / `{{POST_TIME}}` | 作者昵称 / 发布时间 |
| `{{POST_CONTENT_TEXT}}` | 正文纯文本（去 Markdown 标记，截断 500 字） |
| `{{POST_COVER}}` | 首图 `<figure>`，无图为空 |

正文在首屏只输出纯文本；完整内容由框架注入 `window.__HUBLOG_POST__`，主题 JS 自行渲染 Markdown。模板里要保留 `.content` 节点——前端 `article.js` 用它判断已有 SSR 内容。

### 7.4 框架注入项总表

| 注入项 | 用途 |
| --- | --- |
| `<base href="/templates/{id}/">` | CSS / JS / JS 内图片的相对路径基准 |
| `window.HUBLOG_BASE_URL` | 站点根路径 |
| `window.HUBLOG_URL_REWRITE` | 伪静态开关布尔值 |
| `window.HUBLOG_PAGE_BASE` | 页面 URL 前缀 |
| `window.__THEME_OPTIONS__` | 当前主题外观选项对象（首屏即可用，无需等异步接口） |
| `window.__HUBLOG_POST__` | 详情页完整文章数据（JSON） |
| `{{PAGE_BASE}}` | 页面 URL 前缀，用于站内绝对路径 |
| `{{PAGE_TITLE}}` / `{{PAGE_DESCRIPTION}}` / `{{PAGE_KEYWORDS}}` | SEO 标题 / 描述 / 关键词 |
| `{{POST_ID}}` | 详情页文章 id（非详情页为空） |
| `{{POST_IMAGE}}` | 详情页首图 URL 纯文本（无图为空） |
| `{{PAYWALL_HTML}}` | 付费墙 HTML（框架按付费状态注入，主题无需自建） |
| `window.HUBLOG_FOOTER_DATA` | 页脚数据（站点名 / 备案号 / 执行时间 / 年份 / 友链） |
| `{{SSR_META}}` | 由 SSR 渲染器返回键 `meta` 映射，页面 meta 标签 |

所有未被填充的 `{{SSR_*}}` / `{{POST_*}}` 在输出前统一清空，不会以纯文本形式进入首屏。

## 8. `settings.json` 外观选项

放一份即在后台「扩展管理 → 外观主题」生成表单，无需改后台代码。

| type | 控件 | 说明 |
| --- | --- | --- |
| `text` | 单行文本 | 保存时净化并截断 200 字 |
| `textarea` | 多行文本 | 净化并截断 2000 字 |
| `color` | 取色器 | 校验十六进制色值 |
| `select` | 下拉 | 配 `options: [{value,label}]`，按白名单校验 |
| `switch` | 开关 | 布尔 |
| `number` | 数字框 | |
| `image` | 图片地址 | 校验 http(s) 绝对地址或站点根相对路径，且长度 ≤ 500 |

未知 `type` 回退按 `text` 处理（净化并截断 200 字）。

字段可带 `key`（必填）、`type`、`label`、`desc`、`default`、`options`、`group`（分组名，后台按 group 渲染为标签页），以及首屏样式自描述字段 `cssVar`、`cssUnit`、`cssRule`：

| 字段 | 作用 |
| --- | --- |
| `cssVar` | 写入 `:root` 的 CSS 变量名，如 `--brand`、`--maxw`；变量名须匹配 `/^--[a-zA-Z0-9-]+$/` |
| `cssUnit` | 数值类字段的单位，填 `px` 时追加，如内容宽度 |
| `cssRule` | 整段 CSS 规则模板，用 `%s` 作为净化后值的占位符，仅 `image` 类型生效（背景图 / 渐变等复合规则） |

```json
{
  "fields": [
    { "key": "brand_color", "type": "color", "label": "品牌主色", "default": "#0E7C6B", "cssVar": "--brand" },
    { "key": "content_width", "type": "select", "label": "内容宽度", "default": "1180", "cssVar": "--maxw", "cssUnit": "px",
      "options": [ { "value": "1080", "label": "紧凑" }, { "value": "1180", "label": "标准" } ] }
  ]
}
```

框架按 schema 通用遍历这些声明，把配色 / 宽度写成首屏内联样式，把完整选项挂到 `window.__THEME_OPTIONS__`。**新增选项只需在 `settings.json` 声明，不需要改 `index.php`，也不需要写前台映射。** 所有写入值按字段类型做白名单校验，`cssRule` 的 `%s` 只接受净化后的 URL。

| 环节 | 说明 |
| --- | --- |
| 落库 | `settings` 表，key = `theme_opts_{主题id}`，value 为 JSON；各主题独立存档 |
| 读 / 存 | 后台 SPA 调 `GET` / `PUT /api/index.php/.../theme-options`；按 schema 校验，只落声明过的键 |
| 上传图片 | `POST .../theme-options/upload` |
| 下发 | `GET /api/site/config` 响应含 `theme_options`（默认值与存档合并） |
| 应用 | 首屏读 `window.__THEME_OPTIONS__`，JS 运行时读 `app.siteConfig.theme_options` |

## 9. 启用与切换

| 方式 | 操作 |
| --- | --- |
| 后台 | 扩展管理 → 外观主题 → 选卡片保存，前台刷新生效 |
| 改库 | `settings` 表写 `key=active_theme, value={id}`，并清除 `site_settings` 缓存 |
| 回退默认 | 写回 `moments`，或置为任意非法值（自动回退） |

当前主题经 `site_settings` 缓存读 `active_theme`（前台 TTL 3600 秒，`index.php` 与 `Theme::current()` 共用），后台切换后需清 `site_settings` 缓存才即时生效。

## 10. JS 约定

- `assets/js/app.js` 为 `type="module"`，静态 `import` 各 `./modules/*.js`；每个 HTML 都要引入。
- 入口以静态 `import` 为主（基准 moments 的 `compress.js` 存在一处 `await import('./config.js')` 动态 import）；任一静态 `import` 目标缺失会导致整个模块图加载失败。
- 页面分发按 DOM 锚点判断，避免占用首页分支使用的通用 id。
- 请求统一走 `assets/js/modules/api.js`；登录态以 `app.authed` 为准（`null` 未确认 / `true` 已登录 / `false` 未登录，由 `/auth/me` 确认）。令牌在 httpOnly Cookie 中，JS 读不到。
- 用户内容必须经 `renderMarkdown()`（marked + DOMPurify）后渲染，禁止直接插入原始字符串。
- 内联 `<script>` 必须闭合，改完核对开闭标签数量相等。
- 同一功能需在多套主题保持一致时，逐套同步，并升对应 `?v=`。

### 10.1 正文格式与正文内媒体契约

`theme.json` 必须声明 `content_format`（`markdown` / `html`），表示写页提交给 `posts.content` 的正文格式。支持在正文任意位置插入媒体时再声明 `inline_media: true`。正文里的媒体一律写成纯文本占位符，占位符不含 URL：

```
[[media:<type>:<index>]]
```

| 项 | 规范 |
| --- | --- |
| `type` | `image` / `video` / `attachment`，分别对应 `images` / `videos` / `attachments` |
| `index` | 对应数组的 0-based 下标 |
| 位置 | 独占一行，不得与其它文字同行；同一 `(type, index)` 在一条正文里只出现一次 |
| 字符集 | 仅小写字母、冒号、十进制数字；不含 URL、引号、标签 |

占位符是纯文本，`Security::purify()`、`strip_tags`、marked、DOMPurify 均原样保留；正文格式不同不影响它存活。禁止在正文里直接写 `<video>` / `<source>` 等媒体标签，也禁止把 URL 写进占位符。

**发布侧**

| 环节 | 规范 |
| --- | --- |
| 上传 | `POST /posts/upload`、`POST /posts/upload-video`、`POST /posts/upload-attachment` |
| 配额 | 读 `GET /site/config` 的扁平键 `upload_max_images` / `upload_max_videos` / `upload_max_attachments`；`limits.*` 嵌套结构与 `video_enabled` 是 `/api/app/config`（App 端）的口径，不在 `/site/config` 返回中 |
| 提交 | 上传返回的 URL 必须同时写入占位符对应的 `images` / `videos` / `attachments`；只写正文不写数组，`recordUploads()` 不会绑定 `post_id`，文件会被当作孤儿上传清理 |
| 数组形态 | `images`：`string[]`；`videos`：`string[]` 或 `[{url, cover, duration}]`；`attachments`：`[{url, filename, size}]` |
| 编号固化 | 提交前按占位符在正文里出现的顺序重排数组，并把 `index` 重编号为最终下标；删除某个媒体时不重排其余数组项 |
| 开关 | 新增站点开关须同步多处：`AdminSettingsController::settings()` 的 `$allowed`、`AdminSettingsController::siteConfig()`（`/site/config` 下发）、`FeatureFlags::publicPayload()`、`AppController::config()`（`/api/app/config`）、`PostController::create()`，并清 `site_settings` 缓存 |

**渲染侧**

1. 先净化正文（用户内容必须经 `renderMarkdown()`），再替换占位符。
2. URL 只从接口下发的结构化数组按 `index` 取，不从正文解析；写入 DOM 前按 `^(https?://|/)` 校验协议。
3. 索引越界、类型不符、媒体已下架 → 渲染为「图片不可用 / 视频不可用 / 附件不可用」纯文本，不得把 `[[media:` 原文留在页面上。
4. 首屏 `{{POST_CONTENT_TEXT}}` 由框架统一降级为 `[图片] / [视频] / [附件]`，主题无需处理。
5. 类型帖正文存独立表、`posts.content` 为空；在其中使用占位符须在 `hydratePosts` 的 `build*Data` 里同步下发媒体数组。
6. App 端 markdown-lite 使用同一语法。

**校验**

`node scripts/audit-theme.js` 与 DOM 契约同次校验：`content_format` 是否声明且取值合法、`inline_media` 类型、主题源码里占位符字面量是否符合语法（自造方言即报错）、`inline_media: true` 时是否存在解析实现与 `videos` / `attachments` 提交字段。源码里的语法示例须写在注释中，审计会剥离注释后再校验字面量。占位符的解析与渲染由主题自己实现，新增主题无需改动框架层。

## 11. 版本戳与缓存

- HTML 中 `assets/js/app.js` 的 `?v=` 由框架按 **app.js 及所有 modules 的最新修改时间**自动覆盖；`assets/css/style.css` 的 `?v=` 按其自身修改时间覆盖。主题作者不必手动维护 HTML 里这两个版本号。
- `app.js` 内部 `import './modules/xxx.js?v=...'` 的手写版本戳框架不处理。仓库提供一致性门禁：

```bash
node scripts/check-theme-sync.js           # 检查共享模块字节一致、版本戳一致且与内容匹配
node scripts/gen-asset-version.js --write  # 把 ?v= 回写为对应文件内容 sha1 前 8 位
```

门禁要求同一资源在所有引用处戳值相同，且等于内容 sha1 前 8 位；`--fix` / `--write` 可自动回写。该脚本是仓库级前端一致性检查，主题交付前按需运行。

- 同一功能在多主题同步时，改完记得升版本戳，避免浏览器缓存旧版本。

## 12. 开发步骤

**复用基准 JS（`inherits_js = moments`）**

1. 整目录复制 `templates/moments/` 为 `templates/{id}/`，含 `assets/` 全量副本。
2. 改 `theme.json` 的 `id / name / version / description / preview`，`inherits_js` 保持 `moments`，按实际正文格式保留 `content_format`。
3. 替换 `preview.svg`。
4. 在 `assets/css/style.css` 末尾追加覆盖层，优先改 CSS 变量。
5. 调整 HTML 结构时不删除、不重命名契约 id 与 class；新增样式用新 class。
6. 需要外观选项则加 `settings.json` 并在字段上声明 `cssVar` / `cssUnit` / `cssRule`。
7. `node scripts/audit-theme.js {id}` → 关键契约 0 缺失。
8. 后台启用，逐页验证。

**独立前端栈（参考 `templates/zixunfeed/`）**

1. 建目录与 18 个 HTML 骨架，每页引入 `app.js`。
2. 先列接口清单（`/posts/timeline`、`/app/categories`、`/site/config`、`/search`、`/auth/me`、`/csrf` …），再写 `app.js` 与各模块。
3. `theme.json.inherits_js` 填自身主题 id，按写页实际格式声明 `content_format`；支持正文内媒体再加 `inline_media: true`。
4. 需要首屏：放 `ssr.php`（返回 callable）+ `partials/`，用 `{{SSR_*}}` / `{{POST_*}}` 占位符承接，频道锚点写注释形式。
5. 需要外观选项：放 `settings.json`，字段上声明样式映射。
6. 额外页面直接放同名 `.html`。
7. `node scripts/audit-theme.js --gen --theme={id}` 生成 `contract.json`，再跑 `node scripts/audit-theme.js` 全量回归。
8. 逐页验证渲染与交互后后台启用。

## 14. 问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 首页空白、按钮无响应 | ES Module 的静态 `import` 目标缺失，模块图加载失败 | 核对 import 目标；查看控制台报错 |
| 切换主题后外观没变 | `active_theme` 未写入或 `site_settings` 缓存未清 | 核对库值与缓存，检查响应中的 `<base href>` |
| 切换后图片 / CSS 404 | 引用了别的主题目录 | `assets/` 全量复制 |
| 首屏显示 `{{SSR_*}}` 花括号 | 占位符未进入 SSR 管线，或频道锚点写成裸占位符 | 确认 `ssr.php` 返回 callable、返回键与占位符对应；频道改 `<!--{{SSR_CHANNELS}}-->` |
| 首屏有内容但都被注释吞掉 | 注入的 `<a>` 落在 HTML 注释内 | 用注释锚点写法，让框架先整体替换 |
| 首屏服务端有内容、JS 接管后闪变 | SSR 结构与前端模块渲染结构不一致 | 对齐两边 DOM 结构 |
| 页面空白、`window.app` 不存在 | 内联 `<script>` 漏 `</script>` | 核对标签配平 |
| 独立主题被报大量契约缺失 | 按基准主题基线校验了独立前端栈 | `inherits_js` 填自身 id |
| 复制型主题未做关键契约校验 | `inherits_js` 填了自身 id | 改成 `moments` 后重跑审计 |
| 非首页正文 Markdown 不解析 | vendor 脚本只在首页引入 | 所有渲染正文的页面引入 marked / DOMPurify |
| 审计报「未声明 content_format」 | 新主题缺声明 | 按写页实际格式补 `markdown` / `html` |
| 审计报「非法媒体占位符」 | 自造方言，或把 URL 写进占位符 | 统一改用 `[[media:<type>:<index>]]`；语法示例写进注释 |
| 首屏出现 `[[media:` 原文 | 占位符没走框架纯文本降级 | 核对 `type` 取值与下标为十进制数字 |
| 设计稿被扫描工具当页面 | 扫描按 `*.html` 全量收集 | 放主题目录之外；文件名含「预览 / preview」仅在独立主题的 `app.js` 引入检查中被忽略，仍会被扫描 |
