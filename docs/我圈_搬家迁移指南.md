# 我圈 搬家 / 迁移指南

> 适用于把我圈从一台服务器迁移到另一台服务器，或换域名、换目录部署。
> 代码内部常量仍沿用 `HUBLOG_*`（如 `HUBLOG_BASE_URL`），属历史命名，**勿改**。
> 结论先行：**真正需要改内容的文件只有 1 个 —— `config.php`**，其余都是"原样带过去"和"按新服务器环境配一次"。

---

## 一、搬家前：先采集这些信息

在旧站点上把下面几项记录下来，搬家后逐项核对。

| 项目 | 从哪里看 | 说明 |
|---|---|---|
| 程序版本 | `config.php` 的 `APP_VERSION` | 决定新环境 PHP 版本要求 |
| PHP 版本与扩展 | `php -v` / `php -m` | 需 `PDO`、`PDO_MySQL`、`GD`、`JSON`、`cURL` |
| 数据库名 / 用户 / 端口 | `config.php` 的 `DB_*` | 搬家后要改 |
| 数据库版本标记 | `cache/.schema_version` | 迁移系统进度（如 `101`），一并带走 |
| 上传目录体积 | `du -sh uploads/` | 决定打包与传输方式 |
| URL 模式 | 后台设置 / `settings` 表 `url_rewrite` | `0` = PATH_INFO（默认，不依赖伪静态） |
| 站点地址 | `settings` 表 `site_url` | 很多站点**没有设置**这一项，搬家后要补 |
| 授权配置 | `settings` 表 `license_bind_domain` | 若绑定了域名，换域名需重新授权 |

快速采集命令：

```bash
# 数据库规模
mysql -u 用户 -p -e "SELECT COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA='库名';"

# 数据规模
mysql -u 用户 -p 库名 -e "SELECT (SELECT COUNT(*) FROM users) 用户数, (SELECT COUNT(*) FROM posts) 动态数, (SELECT COUNT(*) FROM uploads) 上传数;"

# 上传目录体积
du -sh uploads/
```

## 二、必须修改的文件（改内容）

| 文件 | 要改什么 | 不改会怎样 |
|---|---|---|
| **`config.php`** | `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASS` | 全站 500，数据库连不上 |
| `config.php` → `JWT_SECRET` | **建议**重新生成 64 位随机串 | 不改也能跑；改了所有已登录用户强制下线（搬家后反而更安全） |
| `config.php` → `MEDIA_BASE_URL`（如需，在 `config.php` 中新增 `define('MEDIA_BASE_URL', 'https://新域名');`，`config.example.php` 有示例） | 仅当 App/小程序/CDN 需要完整图片 URL 时填 `https://新域名` | 不改则自动从当前请求推导，PC 网页端不受影响 |
| `config.php` → `CORS_ALLOWED_ORIGINS`（如需，在 `config.php` 中新增 `define('CORS_ALLOWED_ORIGINS', '域名1,域名2');`，`config.example.php` 有示例） | 有跨域调用时填新域名白名单（默认 `*`） | 跨域请求被拒 |

> 后端主配置以 `config.php` 为准，别去改模板文件。注：`api/core/EnvLoader.php` 是未接入的遗留类（全仓无实例化），`.env` 不参与配置加载；`.env.example` 仅为模板，配置以 `config.php` 的 `define()` 为唯一来源。
> `APP_URL`、`TIMEZONE`（Asia/Shanghai）一般无需改动。

**config.php 需要修改的段落：**

```php
define('DB_HOST', 'localhost');      // 新库地址，远程库填 IP
define('DB_PORT', '3306');
define('DB_NAME', '新库名');
define('DB_USER', '新用户名');
define('DB_PASS', '新密码');
define('JWT_SECRET', '重新生成的64位随机字符串');
```

生成新密钥：

```bash
openssl rand -hex 32
# 或
php -r "echo bin2hex(random_bytes(32));"
```

## 三、必须原样带走的文件 / 目录（漏了就打不开）

| 路径 | 说明 | 丢失后果 |
|---|---|---|
| **根目录 `.installed.lock`** | 安装锁（**当前版本在站点根目录**；旧版名 `cache/install.lock`，新版代码两者都识别） | ⚠️ **致命**：检测不到就 302 跳转到 `install.php`。若该文件还在，会进入安装向导（有重置数据风险）；若已删除，则直接 404 白屏 |
| **DB `schema_versions` 表 + `cache/.schema_version` 文件** | 迁移版本标记（如 `101`） | **双写、DB 优先**：优先从 `schema_versions` 表读，表不存在才降级到 `cache/.schema_version` 文件。两者都保留最稳妥 |
| **`uploads/` 整个目录** | 全部图片 / 视频 / 头像 / 附件 | 所有媒体 404。数据库存的是相对路径 `/uploads/images/2025/05/23/xxx.jpg`，**目录必须放在站点根目录下且名称不变** |
| **`templates/`** | 前端模板 | 首页报"模板文件缺失" |
| `admin/` `api/` `plugins/` `sql/` | 程序主体 | 无法运行 |
| **数据库全量导出 SQL** | 全部业务数据 | 数据全丢 |

> `.gitignore` 已排除 `config.php`、`cache/*`、`uploads/*`、`logs/*` 与 `backups/*` ——
> **如果用 `git clone` 方式搬家，以上几项必须手动补传。**

## 四、不需要改的（程序会自动适配，别多此一举）

| 项目 | 为什么不用改 |
|---|---|
| `index.php` 里的 `$base` / `HUBLOG_BASE_URL` | 从 `SCRIPT_NAME`（含 PATH_INFO 剥离逻辑）动态推导，根目录 / 子目录部署都自动适配 |
| `admin/js/core.js` 里的 `API_BASE` | 从 `window.location.pathname` 推导 |
| `api/core/PathResolver.php` | 自动推导 baseUrl，用于密码重置邮件、OAuth 回调、sitemap |
| 数据库 `uploads.url`、`users.avatar` | 存的都是**相对路径**，换域名无需批量替换 |
| 模板里的 `HUBLOG_PAGE_BASE` | 由 `url_rewrite` 开关 + base 自动计算 |

## 五、数据库迁移

### 导出（旧服务器）

```bash
mysqldump -u 用户 -p --default-character-set=utf8mb4 --single-transaction --routines --triggers 库名 > woquan_backup.sql
```

### 导入（新服务器）

```sql
CREATE DATABASE 新库名 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

```bash
mysql -u 新用户 -p 新库名 < woquan_backup.sql
```

### 导入后要确认 / 修改的数据（`settings` 表）

| 键 | 处理建议 |
|---|---|
| `site_url` | ⚠️ 很多站点没设置，必须补，影响 canonical、OG 分享、sitemap |
| `url_rewrite` | 默认 `0`（PATH_INFO），保持即可；新服务器配好伪静态后再考虑开 |
| `site_icp` / `site_stats_code` | 按需填 |
| `ai_comment_api_url` 等 | 新服务器没装 Ollama 就不用管（AI 功能默认关闭） |
| `mail_*` | 若启用邮箱验证需重配 SMTP |
| `license_bind_domain` | 若绑定了旧域名，换域名需重新授权 |

> ⚠️ **改 settings 请走后台**，直接改数据库会因 `site_settings` 的 1 小时缓存而延迟生效。

补 `site_url`：

```sql
INSERT INTO settings (`key`, `value`) VALUES ('site_url', 'https://你的新域名')
ON DUPLICATE KEY UPDATE `value` = 'https://你的新域名';
```

## 六、新服务器环境要求

| 类别 | 要求 |
|---|---|
| PHP | ≥ 8.0（建议 8.1+） |
| 必需扩展 | `PDO`、`PDO_MySQL`、`GD`、`JSON`、`cURL` |
| 推荐扩展 | `fileinfo`（MIME 校验，缺失自动降级）、`redis`（可选缓存） |
| MySQL | ≥ 5.7 |
| 可选依赖 | `FFmpeg`（私信视频转码，缺失自动跳过）、`Ollama`（本地 AI） |
| 可写目录 | `uploads/`、`cache/`、`logs/`、`backups/`、`tmp/` |
| PHP 上传限制 | `upload_max_filesize` ≥ 10M、`post_max_size` ≥ 10M |

**Linux 下设置权限（以 www-data 为例）：**

```bash
chown -R www-data:www-data /path/to/woquan
find /path/to/woquan -type d -exec chmod 755 {} \;
find /path/to/woquan -type f -exec chmod 644 {} \;
chmod -R 775 uploads cache logs backups tmp
```

## 七、Web 服务器配置（四选一，只需配一个）

| 环境 | 用哪个文件 | 关键改动点 |
|---|---|---|
| **Nginx（标准 / 宝塔）** | `nginx.conf` | 把 `location` 块复制进站点 `server {}`；`fastcgi_pass 127.0.0.1:9000` 改成实际的 `unix:/run/php/php8.1-fpm.sock` 或对应端口 |
| **Apache** | `.htaccess`（项目自带） | 需开启 `mod_rewrite`；⚠️ 若 PHP 走 `php-fpm`（proxy_fcgi），`php_value` / `php_flag` 那几行会导致 **500 错误**，需删除或改在 `php.ini` 设置 |
| **Caddy v2** | `Caddyfile` | 把 `example.com` 换成真实域名；`php_fastcgi` 地址按实际改 |
| **IIS** | `web.config` | 需安装 URL Rewrite 模块 |

**宝塔面板最省事的做法**：站点 → 伪静态 → 粘贴 README 中"Nginx 宝塔面板专用"那一整块，并确认已启用 `pathinfo.conf`。

> `nginx.conf` 里已内置安全规则：`backups/ cache/ logs/ sql/ docs/` 全部 deny，`.zip/.sql/.md/.env` 等拒绝访问，`uploads/` 下禁止执行 PHP。**这些规则建议一并搬过去**，不要只搬路由部分。

## 八、搬家后必做（按顺序）

1. **清空缓存**：删除 `cache/` 下所有 `.cache` 文件和 `.index`
   ```bash
   rm -f cache/*.cache cache/.index
   ```
   > `site_settings` 有 1 小时缓存，不清会继续用旧配置；之后每次改 settings 也建议清一次。

2. **不要删除 `.installed.lock`（安装锁在站点根目录）**
   ```bash
   ls -l .installed.lock cache/.schema_version   # 这两个标记必须还在
   ```
   > ⚠️ **网站的"已安装"标记是根目录 `.installed.lock`**（旧版名 `cache/install.lock`，新版代码两者都识别）。
   > 清理缓存时**千万不要图省事 `rm -rf cache/*` 或清空整个目录** —— 一旦 `.installed.lock` 没了，`index.php` 会判定"尚未安装"，访问首页自动跳转到 `install.php`：
   > - `install.php` 还在 → 进入安装向导，有误操作重置数据的风险；
   > - `install.php` 已删除 → 直接 404 白屏。
   >
   > 同一个目录下的 `cache/.schema_version`（数据库迁移版本标记）也要保留。
   > 清缓存只删 `*.cache` 和 `.index` 这两个模式即可，锁文件不受影响。

3. **后台补 `site_url`**：系统设置 → 站点地址（或执行上面的 SQL）。

4. **检查伪静态开关**：保持 `url_rewrite=0`，PATH_INFO 模式不依赖重写规则，最不容易出问题。

5. **验证清单**
   - [ ] 首页能打开、动态列表正常
   - [ ] 图片 / 附件能显示（说明 `uploads/` 搬对了）
   - [ ] 后台 `/admin/` 能登录，API 无跨域报错
   - [ ] 发布一条带图动态 + 上传附件成功
   - [ ] 个人主页、话题页、详情页 `/p/1` 正常
   - [ ] 点赞、评论、私信功能正常
   - [ ] 查看 `logs/` 下有无新报错

## 九、常见坑（按踩坑概率排序）

| 坑 | 现象 | 解决 |
|---|---|---|
| **丢掉 `.installed.lock`**（漏传，或清缓存时误删；旧版名 `cache/install.lock`） | 首页 302 后进安装向导或 404 | 传回根目录 `.installed.lock`；清缓存只删 `*.cache` / `.index`，**勿清空整个 `cache/`**；极端情况可新建 `.installed.lock`（旧版 `cache/install.lock` 亦可） |
| **漏传 `uploads/`** | 页面正常但所有图裂 | 整个目录传回站点根目录，名称不能改 |
| **`.htaccess` 里的 `php_flag` / `php_value`** | Apache + PHP-FPM 环境整站 500 | 注释掉这些行，改在 `php.ini` 设置 |
| **Windows → Linux 换行符变化** | 后台提示"文件被篡改"、功能降级 | 项目有文件哈希校验（`file_hashes` 表）；**必须用 zip 二进制传输，禁用 FTP 文本模式** |
| **目录不可写 / 属主错误** | 上传失败、缓存写入失败 | `chown -R www-data` + `chmod 775` |
| **缓存残留旧域名** | canonical、分享链接还是旧地址 | 清 `cache/*.cache` 和 `cache/.index` |
| **`site_url` 未设置** | OG / canonical 只有相对路径 | 后台或 SQL 补上 |
| **PHP 版本低于 8.0** | 语法错误、白屏 | 升级 PHP |
| **上传大小限制** | 大图上传失败 | 改 `php.ini` 的 `upload_max_filesize` / `post_max_size`（Nginx 下 `.htaccess` 不生效） |
| **git clone 搬家漏文件** | 缺 `config.php` / `uploads` / `cache` | `.gitignore` 排除了这些，必须手动补传 |

## 十、最小搬家步骤（TL;DR）

```bash
# 1. 旧服务器：打包 + 导库
mysqldump -u 用户 -p --default-character-set=utf8mb4 --single-transaction 库名 > woquan.sql
zip -r woquan.zip . -x "*.git*"          # 二进制打包，别用 FTP 文本模式

# 2. 新服务器：解压 + 导库
unzip woquan.zip && mysql -u 新用户 -p 新库名 < woquan.sql

# 3. 只改一个文件
vi config.php        # DB_HOST / DB_NAME / DB_USER / DB_PASS（+ 可选 JWT_SECRET）

# 4. 权限
chmod -R 775 uploads cache logs backups tmp

# 5. 清缓存
rm -f cache/*.cache cache/.index

# 6. 配 Nginx / Apache（见第七节），然后逐项跑第八节验证清单
```
