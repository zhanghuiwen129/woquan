# 我圈 数据库结构说明

## 1 概览

| 项 | 值 |
| --- | --- |
| 表数量 | 85（契约 `REQUIRED_TABLES` 口径，含扩展闭环新增 3 表） |
| 引擎 / 字符集 | InnoDB / `utf8mb4_unicode_ci` |
| 当前迁移版本 | `currentVersion = 101`（`api/core/Migration.php`） |
| 最大迁移方法 | `migrate101()`（`api/core/MigrationBatchC.php`，创建 `plugin_states` / `plugin_configs` / `pages`） |
| 契约基线 | `api/core/MigrationContract.php` 的 `REQUIRED_TABLES`（85）、`REQUIRED_COLUMN_NAMES`（89）、`CRITICAL_COLUMNS`（52 组）、`REQUIRED_UNIQUE_INDEXES`（19 组） |
| 迁移扫描源文件 | `Migration.php`、`MigrationHistory.php`、`MigrationBatchA.php`、`MigrationBatchB.php`、`MigrationBatchC.php` |
| 建表入口 | `Migration::run()`，被 `index.php`、`api/index.php`、`install.php`、`api/core/Upgrade.php` 调用 |
| 初始化脚本 | `sql/hublog.sql`（仅建 `schema_versions` 与版本 0 记录） |

`attachments` 不是表，是 `posts.attachments` JSON 列；附件记录落在 `uploads`。`site_settings` 不是表，是缓存键，数据源为 `settings` 表。

| 表 | 列 | 键 |
| --- | --- | --- |

| `plugin_configs` | `id` bigint unsigned AUTO_INCREMENT、`plugin_name` varchar(64)、`config_key` varchar(128) snake_case、`config_value` text、`updated_at` datetime | PRIMARY KEY `id`；UNIQUE `uk_plugin_config(plugin_name,config_key)` |
| `pages` | `id` int unsigned AUTO_INCREMENT、`slug` varchar(64)、`title` varchar(128)、`content` longtext、`status` tinyint(1) DEFAULT 0（0 草稿 / 1 发布）、`template` varchar(64) DEFAULT ''、`seo_title` varchar(160) DEFAULT ''、`seo_description` varchar(300) DEFAULT ''、`seo_keywords` varchar(200) DEFAULT ''、`sort_order` int DEFAULT 0、`source` varchar(16) DEFAULT 'manual'（`manual/seed`）、`created_at`、`updated_at` | PRIMARY KEY `id`；UNIQUE `uk_page_slug(slug)`；`idx_page_status_sort(status,sort_order)` |

说明：

- `plugin_states` 是插件启停与安装状态的唯一可信源；`Cache('plugin_states')`（TTL 300）只是读缓存，写后即失效；旧 `disabled_plugins` 黑名单一次性幂等迁入。
- `plugin_configs` 按 `(plugin_name, config_key)` 隔离，核心 `settings` 白名单不新增插件键；`config_key='_schema_tables'` 为核心保留键（登记插件建表归属），插件不可读写。
- `pages` 的协议种子行 `slug=agreement_{user|privacy|realname}` 以 `source='seed'`、`status=0` 导入，避免升级覆盖运营内容；`/api/app/agreements` 正文优先取已发布单页，依次回退 `settings.agreement_*_text` 与控制器缺省正文。
- 插件自建表必须以 `plugin_` 开头（示例：`plugins/DemoExtension` 声明 `plugin_demo_notes`），不得与 `MigrationContract::REQUIRED_TABLES` 同名；DDL 由核心生成，插件不写裸 SQL。

## 4 迁移治理

### 4.1 版本记录

| 项 | 值 |
| --- | --- |
| 表 | `schema_versions`（`version` UNIQUE、`applied_at`、`id`） |
| 读版本 | `SELECT MAX(version) FROM schema_versions` |
| 写版本 | 先 `DELETE FROM schema_versions WHERE version >= ?`，再 `INSERT (version, applied_at)` |
| 文件镜像 | `cache/.schema_version` |
| 校验标记 | `cache/.schema_verified`，JSON `{version,time}`，TTL 300 秒 |
| 失败标记 | `cache/.migration_failed`，JSON `{time,target_version,error}`，供 `/health` 的 `migration` 检查读取 |
| 数据库锁 | `SELECT GET_LOCK('hublog_migrate', 0)`；取不到锁时非迁移请求直接返回 |
| 登记跳号 | `INTENTIONAL_GAPS = [60, 64]` |

### 4.2 run() 流程

| 阶段 | 行为 |
| --- | --- |
| 1 | 同请求内 `self::$checked` 只执行一次 |
| 2 | `verificationCacheFresh()` 命中则直接返回，不执行任何迁移 SQL |
| 3 | `acquireLock()` |
| 4 | `getInstalledVersion()`：DB `MAX(version)` → `cache/.schema_version` → `users` 表存在则 0、否则 -1 |
| 5 | 版本已 ≥ 101 时仍执行 `schemaDiff()`：契约完整则 `markVerified()` 返回；缺表回退版本 0、缺列回退 25 后重跑 |
| 6 | 全新安装（`version < 0`）：`buildFullSchema()` → `migrate36..101` → 终态校验 → `saveVersion(101)` |
| 7 | 增量升级：逐版 `applyMigration()` 后即 `saveVersion($v)` → 终态校验 → `markVerified(101)` |
| 8 | 异常写 `error_log` 与失败标记；`APP_DEBUG` 为真时重抛 |
| 9 | 释放锁 |

`applyMigration()`：`method_exists` 则调用 `migrate{$version}`；否则仅当版本号在 `INTENTIONAL_GAPS` 内才跳过，其余抛 `RuntimeException`。

### 4.3 新增迁移规范

```bash
# 1. 在对应 Batch 文件中新增 migrateNN()，并把 Migration.php 的 $currentVersion 改为 NN
# 2. 重新生成契约
php scripts/build_migration_contract.php --write
```

| 规则 | 说明 |
| --- | --- |
| 不允许手改 `buildFullSchema()` | V36 之后由循环补跑覆盖 |
| 新表必须进入 `MigrationContract::REQUIRED_TABLES` | 由生成器扫描 5 个源文件得出 |
| DDL 单句 try/catch 会吞掉失败 | 由 `run()` 的终态契约校验统一兜底；失败回退版本号并写 `cache/.migration_failed` |
| 末尾自检 | 每个 `migrateNN` 用 `information_schema` 复查表/列；全局由 `MigrationContract::diff()` 校验 85 表 + 89 列名 + 52 组精确列 + 19 组唯一索引 |

`CRITICAL_COLUMNS` 精确哨兵（52 组中的节选，完整清单以 `MigrationContract::CRITICAL_COLUMNS` 为准）：`posts.location`、`posts.location_lat`、`posts.is_anonymous`、`posts.mentions`、`posts.declaration`、`posts.audit_state`、`posts.is_original`、`comments.is_ai`、`users.cover`、`polls.post_id`、`badges.display`、`shop_products.discount_mode`、`shop_products.discount_value`、`shop_products.vip_levels`、`shop_products.valid_days`、`user_coupons.order_id`。

旧 `criticalTablesExist()` / `criticalColumnsExist()` 已移除，终态自检统一走 `MigrationContract::diff()`；`api/tests/MigrationContractTest.php` 有断言确认源码中不再出现 `criticalTablesExist()`。
